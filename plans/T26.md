## 1. `src/traits.js` (new, no imports)

```js
// Traits (T26): small facts about ONE creature (not its species), drawn once and saved. A trait does nothing by
// itself: the feature that uses it reads it (riding reads 'rideable'). New trait = one more entry here.
export const TRAITS = {
  rideable: {
    text: 'Can be ridden',                                  // card badge
    book: 'About 1 in 4 of them can be ridden. Look for the badge!',
    caught: name => `Lucky! This ${name} can be ridden.`,   // toast after a catch
    grown: name => `${name} is big enough to ride now!`,    // after evolving (must not contain "evolved into")
    chance: 0.25,
    // Who may have it, and how T27 rides it: 'land' | 'water' | 'sky'.
    species: { /* list in §2 */ },
  },
};
```

Exported functions:
- `hash32(s)`: FNV-1a then fmix32:
  ```js
  let h = 0x811c9dc5;
  for (let i = 0; i < s.length; i++) { h ^= s.charCodeAt(i); h = Math.imul(h, 0x01000193); }
  h ^= h >>> 16; h = Math.imul(h, 0x85ebca6b); h ^= h >>> 13; h = Math.imul(h, 0xc2b2ae35); h ^= h >>> 16;
  return h >>> 0;
  ```
- `traitRoll(seed, id) = hash32(`${seed}|${id}`) / 2**32` (never `Math.random`, never `battle.rng`).
- `canHave(id, species)` = `!!TRAITS[id]?.species[species]`.
- `drawTraits(c)`: ids in `TRAITS` order with `canHave(id, c.species)` and `traitRoll(String(c.uid), id) < chance`. Level not used.
- `cleanTraits(list, species)`: keeps known, allowed ids once each; non-array -> `[]`.
- `ensureTraits(c, fallbackKey)` -> changed?: missing/empty `uid` -> `c.uid = 'o' + hash32(fallbackKey).toString(36)`; `traits` array -> `cleanTraits` (a saved `[]` stays `[]`), else `drawTraits(c)`.
- `fixTraits(list, where)`: `list.forEach((c, i) => ensureTraits(c, `${where}:${i}:${c.species}:${c.level}`))`, returns how many changed (`where` = `'party'` / `'box'`).
- `gainTraits(c)` (evolution): `ensureTraits(c, c.uid)`, then push every id of `drawTraits(c)` missing from `c.traits`; returns the added ids. Only adds.
- `hasTrait(c, id)` = `!!c?.traits?.includes(id)`.

`traits` is stored (not recomputed) so later list/chance changes never take a trait away.
