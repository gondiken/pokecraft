# T6 · More attack types (plan)

Goal: ~77 moves (4+ per type, 8 normal) with original names, a small effect system (heal, raise
own attack/defence, lower foe attack/speed, flinch, sleep for one move, multi-hit, recoil, never
miss, plus the existing priority), richer learnsets (`L(type, second, extra)`), a few signature
moves, and a "Learn X? Forget which move?" prompt in battles. Player battles must stay in sync.

Parallel work: **T3 (Caves)** edits `world.js`, `creatures.js` and adds `SPAWNS.cave` in
`species.js`. T6 stays off `world.js`/`creatures.js`; in `species.js` it only touches `MOVES`,
the `T1/T2/T3/T4/UTIL/SECOND` tables, `L()`, the `learn:` field of each species, `makeCreature`,
`gainXp` and a new `moveInfo()`. No reformatting elsewhere.

Files: `src/species.js`, `src/battle.js`, `src/book.js`, `src/sound.js`, `src/duel.js`
(version guard only), `style.css` (prompt card + card tags), `tests/helpers.mjs`,
`tests/specs/moves.mjs` (new), small edits to `pvp`, `new-types`, `sound` specs, `README.md`,
`CLAUDE.md`. One Sonnet builder is enough; do the steps in order (data first, then battle).

## 1. Move data — `src/species.js` `MOVES`

Format (one effect per move, kept small):
```js
// fx kinds: heal {amount} (status, user) · raise {stat:'atk'|'def', chance?} (user)
//           lower {stat:'atk'|'spd', chance?} (foe) · flinch {chance} · sleep {chance?}
//           multi {min, max} · recoil {amount}
// power 0 = status move (no damage). sure: true = never misses. sig: true = signature move.
restup: { name: 'Rest Up', type: 'normal', power: 0, acc: 1, fx: { kind: 'heal', amount: 0.5 } },
```
`chance` missing = always (status moves). Stages: +1 / −1 per use, capped at ±3.

**Keep every existing id** (saves store ids). Existing names that are real Pokémon move names are
renamed for display only (ids stay): see Decision 1. New ids must not clash with sound effect
names in `sound.js` `SOUNDS` (`heal`, `hit`, `miss`, `super`, `star`, `rainbow`, `thunder`,
`powerup`, `boss`, `win`, `ask`, `cube`...), because `useMove` calls `sound.play(moveId)`.

## 2. Learnsets — `L(type, second, extra)`

```js
const T3 = { fire: 'flarekick', water: 'soakshot', grass: 'seedvolley', electric: 'staticsnap', rock: 'rumblerock',
  ice: 'chillwind', bug: 'buzzdive', ghost: 'boo', mind: 'mindtrick', metal: 'rivetshot', toxic: 'goopshot',
  pixie: 'glitterpuff', drake: 'clawrake', rainbow: 'colorsplash', cosmic: 'meteorshower', sound: 'shriek' };
const T4 = { fire: 'infernodash', water: 'bigwave', grass: 'sapsip', electric: 'stormcall', rock: 'boulderdrop',
  ice: 'glacierslam', bug: 'silkwrap', ghost: 'gloomwave', mind: 'deepfocus', metal: 'ironwall', toxic: 'stinkbomb',
  pixie: 'sweetdreams', drake: 'drakecharge', rainbow: 'shimmer', cosmic: 'supernova', sound: 'lullaby' };
// Types whose T4 is a big hit get a normal helper move at 23; the others get Belly Bash.
const UTIL = { fire: 'pumpup', water: 'restup', electric: 'grumble', rock: 'hunker', ice: 'hunker',
  ghost: 'grumble', toxic: 'hunker', drake: 'pumpup', cosmic: 'restup' };
function L(type, second, extra = []) {
  const base = type === 'normal'
    ? [[1, 'tackle'], [1, 'quickjab'], [8, T1[second]], [12, 'bodyslam'], [19, T3[second]], [23, 'restup'], [28, 'hyperstrike']]
    : [[1, 'tackle'], [1, T1[type]], [7, 'quickjab'], [10, T3[type]], [13, T2[type]], [19, T3[second]],
       [23, UTIL[type] || 'bodyslam'], [28, T4[type]]];
  return [...base, ...extra].sort((a, b) => a[0] - b[0]);
}
```
Rule the builder must keep (the test helpers click the first move): **`makeCreature(id, L).moves[0]`
is a damaging move for every species and level 1–60** (checked by `moves.mjs`). With the table
above the last-4 windows are: 13–18 `[T1,jab,T3,T2]`, 19–22 `[jab,T3,T2,S]`, 23–27 `[T3,T2,S,U]`,
28+ `[T2,S,U,T4]`, 30+ with a signature `[S,U,T4,sig]`.

hand-written learnset). `second` is never `normal`.

## 3. `makeCreature` / `gainXp` (species.js)

- `makeCreature`: unchanged move logic; also set `c.learned` = every learn-entry move ≤ level
  (the "already offered" list, see catch-up). For copies (`knownMoves`) set `learned = moves`.
- `gainXp(c, amount, { ask = false } = {})`. Without `ask` it behaves exactly as today (forget
  the oldest; `book.mjs` calls it outside a battle). Per level-up:
  1. Regular moves at `c.level` not yet known: fewer than 4 moves → learn (`"X learned Y!"`);
     else with `ask` push `{ learn: id }` into `msgs`, without `ask` old behaviour.
  2. **Catch-up** (one per level-up, after 1): the lowest-level learnset move with level < c.level
     that is not in `c.moves` and not in `c.learned` is offered the same way. Old saves: lazily
     `c.learned ??= [...new Set([...c.moves, ...OLD_MOVE_IDS])]` where `OLD_MOVE_IDS` is the 36
     pre-T6 ids, so an existing level-30 team gets the new moves one per level-up instead of nothing
     and is never re-offered old weak moves. Everything learned or declined goes into `c.learned`.
  3. Evolution as today, then also run step 1 against the **new** species at `c.level` (so a
     move at the evolution level is not lost).
  `msgs` may now contain objects; only `Battle.giveXp` passes `ask`. `c.learned` is saved with
  the creature (plain JSON, optional field; no save-version bump). `duel.js teamOf` ignores it.

## 4. Battle effects — `src/battle.js`

**Per-battle state (never saved):** `this.modMap = new Map()` in `start()`;
`mods(c)` returns/creates `{ atk: 0, def: 0, spd: 0, sleep: false, flinch: false, healed: 0 }`.
A creature's mods are cleared **when it comes in**: in `placeAlly()` and `sendOutFoe()`
(`this.modMap.delete(this.ally/foe)`). So switching out resets stat changes and sleep; wild
creatures and party objects never carry anything after the battle. `c.boost` (boss) stays as is.

Helpers: `stage = s => s >= 0 ? (4 + s) / 4 : 4 / (4 - s)` (±3 → ×1.75 / ×0.57, gentle);
`speedOf(c) = Math.floor(statsFor(c).spd * stage(mods(c).spd))`.
- `turn()` and `duelTurn()` use `speedOf` instead of `statsFor(...).spd` for order (both sides
  compute exact mirror values, so duels still agree). Run chance keeps raw speed.
- Damage: `as.atk * stage(ma.atk) * (atk.boost || 1) / (ds.def * stage(md.def))`.

**`useMove(side, moveId, { first = false } = {})`** — new order (comments in code):
1. `ma.flinch` → clear, log `"<who> flinched and couldn't move!"`, return.
2. `ma.sleep` → clear, `sound.play('snooze')`, log `"<who> is fast asleep... Zzz"` then
   `"<who> woke up!"`, return. (Sleep = skip exactly one move.)
3. Existing "used X" line, `sound.play(moveId)`, lunge.
4. **rng #1 (always):** `hit = this.rng()`; miss if `!mv.sure && hit > mv.acc` (status moves too).
5. Status move (`!mv.power`): `await this.applyFx(side, mv)` and return. No more draws.
6. **rng #2 (multi only):** `hits = min + Math.floor(this.rng() * (max - min + 1))`.
7. **rng #3** crit, **rng #4** roll — same order as today, so old moves draw exactly as before.
   One damage number per move; apply it `hits` times (flash each, stop if the target faints),
   the boss "hang on at 1 HP" check runs per hit. Then crit / effectiveness lines, `"Hit 3 times!"`.
8. **rng #5 (only if `mv.fx.chance` exists, always drawn even if the foe fainted or eff 0):**
   effect happens if `roll < chance` and eff > 0 and (foe effects) the target still has HP.
   Moves without `chance` (recoil) always apply.
9. Recoil: `max(1, floor(dealt * amount))`, **never below 1 HP** (Decision 6), log
   `"<who> is hurt by the crash!"`. Then the boss power-up check as today.
No `Math.random()` anywhere in `useMove`/`applyFx`; nothing may branch on `side` before a draw.

**`applyFx(side, mv)`** messages (`who`/`foeWho` use `foeLabel` like today):
- heal: `+floor(maxHp * amount)` capped; `"X got some HP back!"` / `"X's HP is already full!"`; sound `heal`.
- raise: `"X's attack went up!"` / `"X's defence can't go any higher!"`; sound `statup`.
- lower: `"Wild Y's speed went down!"` / `"...can't go any lower!"`; sound `statdown`.
- flinch: only when `first` (the user moved first this turn); sets `md.flinch` silently.
- sleep: `"Wild Y fell asleep! Zzz"`; already asleep → `"But Y is already asleep!"`; sound `snooze`.
`first` is passed by `turn()` (`i === 0`) and `duelTurn()` (`i === 0 && attacks.length === 2`);
`foeTurn()` never flinches. Clear both `flinch` flags at the end of each turn.

**Battle card:** `card()` adds small tags after the HP bar: `ATK ↑2`, `DEF ↑`, `SPD ↓`, `Zzz`.

**Move buttons:** `sub = \`${mv.type} · ${moveInfo(id).text}\`` (keeps `power N` for hits).

**AI (`pickFoeMove`, wild/trainer only, Math.random is fine):** score each move —
hit: `power × eff × stab × (sure ? 1 : acc) × (multi ? 3 : 1)` (0 if eff 0); heal: 120 if HP <
45% and `healed < 1` (heals at most once per creature: easy gyms), else 0; raise: 45 if own
stage < 2 and HP > 60%; lower: 40 if foe stage > −2; sleep: 55 if the foe is awake. 50%: best
score, else a random move with score > 0 (fallback `moves[0]`).

**Catching:** a sleeping foe is a bit easier to catch (`p *= 1.5` before the clamp, Decision 5).

**Log history for tests:** `say()` also pushes text to `this.history` (keep last 60).

## 5. "Learn X? Forget which move?" — `Battle.giveXp` + `askForget(c, id)`

- `giveXp` calls `gainXp(c, xp, { ask: true })` for the active creature and the team share;
  when a msg is `{ learn }`, `await this.askForget(c, learn)`; strings play as today.
- `askForget`: log `"<Name> wants to learn <Move>! Pick a move to forget."`, `sound.play('ask')`.
  `choose()` gets an info item (`{ info: [...] }` renders a non-button `div.b-info.wide`): the new
  move's name, type chip and `moveInfo` text. Then 4 buttons `Forget <Move>` (move colour, sub =
  type · info text), then wide `Don't learn <Move>` last.
  Pick → replace **in place** `c.moves[i] = id`, log `"1, 2 and... poof! X forgot A and learned B!"`,
  `sound.play('levelup')`. Skip → `"X did not learn B."`. Both add `id` to `c.learned`.
  No timeout (waits like `chooseAction`); works with mouse and touch as normal `#b-actions` buttons.
- Where prompts happen: wild, trainer, gym, tower, Coach — every place `giveXp` runs.
  **Duels give no XP** (`foeFainted` returns before `giveXp`; teams are copies), so there are never
  prompts mid-duel. No other code path calls `gainXp` (no rare-candy items; evolution only happens
  inside `gainXp`), so outside battles nothing changes.
- Helpers: `tests/helpers.mjs playBattle` and `pvp.mjs playDuel` now prefer the first enabled
  button whose `small` contains `power ` (fallback first button), so specs never loop on a status
  move or after a prompt swaps a move.
