# T38c · Missions that never end (plan)

Wave 13 (`plans/T38.md`), runs **beside T38a** (Portal Door, Swirl). Read `CLAUDE.md` "Champion missions (T29)", `plans/T29.md`,
`ROADMAP.md` "Wave 13 · The way in". Today `MISSIONS` has 12 hand-written missions; when they are done the panel says
"You finished every mission!" and nothing more happens. T38c adds a **mission maker**: after the 12, Champion Solenne keeps
giving missions made from templates, the same on every device, with treasure spots after the old five and giants that grow.

**Files:** new `src/missiongen.js` (pure: the maker, pools, rounds); `src/missions.js` (state, give/swap/complete, hooks);
`src/treasuremap.js` (new spot list, old five untouched); `src/buildcheck.js` (build templates); `src/coopboss.js` (growth);
`src/duel.js` (`VERSION` 11 + `grow` through `cleanCoop`); `src/missionui.js` (cards, counter); one-line hooks in `src/battle.js`
(catch, giant growth) and `src/rematch.js` (win); tiny `src/main.js` (seed). **No change to `realms.js`, `gymplace.js`,
`world.js`**, no blocks, no `WORLD_VERSION` change (nothing is placed in the world). Mark edits `// T38c` so the merge with T38a
(which also touches `main.js`, maybe `missionui.js`/HUD) is "keep both".

## 0. Decisions

**Decided (orchestrator, 2026-10-24): every recommendation below and in section 12 is taken as written.** The T38a plan puts the Portal Door's box into `world.tower.protect`.

| Question | Recommendation |
| --- | --- |
| Id of a generated mission | `gen:<n>`, n = its mission number, 13, 14, ... (the 12 hand-written ones are 1-12 by list index). |
| Save form | `missions` keeps `{ active, done, last }` and adds `next`, `gen`, `seed`, `spec` (section 1). `done` only ever holds hand-written ids (12 at most); generated ones are a counter. |
| Which seed | The player's **own main-world seed**, stored once in `missions.seed` when the first generated mission is made. Never the world you visit or a realm's seed, so visiting a friend or dreaming never changes your list. |
| Order after the 12 | Rounds of 6 missions: 2 maps, 1 build, 1 catch, 1 rematch-or-build, 1 giant (giant last), the first five shuffled per round from the seed. Round 1 = missions 13-18. |
| A solo player and the 3 hand-written giants | Today a child without a friend is stuck at "This is the only mission left!" with 3 giants. New rule: once every hand-written mission left is a giant, generated missions start; leftover giants stay reachable with "Do a different one". |
| New kinds in wave 13 | **catch** ("Catch a Fire creature") and **rematch** ("Beat the Rock Gym again"). "Find a rare creature at a condition" goes to the backlog (golden hour / night / home conditions are hard to explain and slow for a 7-year-old). |
| Giant growth | +1 "grow" per round: +2 levels on the level cap (55 -> up to `REMATCH_CAP` 65), +0.25 HP factor (at most +1.5). The 3 hand-written giants keep grow 0 (unchanged numbers). |
| Duel `VERSION` | 10 -> **11** (the coop ask carries `grow`; an older helper would build a weaker giant and the two traces would differ). |
| Builds / maps inside a realm | Maps pause (as today). **Builds pause too** (realm edits are thrown away when a realm version changes, so a Dream build is not a safe "done"). Catch, rematch and giants work anywhere. |
| Treasure spot pool | 24 new spots (`MORE_SPOTS`), k = 5..28, made after the five and never moving them; the j-th generated map uses spot `5 + j % 24` (after 24 maps they come round again; the old hole may still be dug: that's fine). |

## 1. Save format and ids

```js
missions: {
  active: 'map3' | 'gen:15' | null,   // as today; old code drops 'gen:..' (missionById fails) and shows "finished", no crash
  done: ['map1', ...],                // hand-written ids only, unique, 12 at most (never grows past that)
  last: 'giant3' | 'gen:14' | null,
  next: 15,          // NEW: the next mission number the maker gives (13 when missing); swap/complete move it on
  gen: 2,            // NEW: generated missions done (the counter; total done = done.length + gen)
  seed: 123456789,   // NEW: the seed the maker uses (set once, integer); missing until mission 13 is made
  spec: { ... },     // NEW: the active generated mission's def as made (kind + params); only while active is 'gen:..'
}
```

- `loadMissions(saved)` keeps today's checks and adds: `next` integer >= 13 (else 13), `gen` integer >= 0 (else 0), `seed` finite
  integer (else null), `active` = `gen:<n>` only when `n === next` and `spec` passes `cleanSpec` (kind known, fields of the right
  type, pools checked: build template id, type name, gym id, boss id, spot k in range); otherwise the maker makes the def again
  from `(seed, n)`. Old saves (T29) have none of the new fields and load as today.
- **Why `spec` is saved:** the maker is pure, so devices on the same code agree anyway; saving the spec only makes sure a code
  update that grows a pool never changes a mission the child is in the middle of. Numbers not given yet may change with an update.
- `missionOf(state, id)` replaces `missionById` in missions.js / missionui.js / coopEnded: a `MISSIONS` entry, or for `gen:<n>` the
  saved `spec` (or `makeMission(n, state.seed)`). `missionById` stays for old callers and the spec.
- Number shown: **Mission N** = `done.length + gen + 1` while one is active or offered (old save with 11 done, giant3 active ->
  "Mission 12"; after it -> "Mission 13"). The id number and the shown number may differ after swaps; only the shown one is text.

## 2. give / swap / "Do a different one"

`nextMission(state, skip)` becomes (pure, missions.js):

1. Hand-written, exactly as today (first not-done after `last`, wrapping, not `skip`), **while some not-done hand-written
   mission is not a boss**.
2. Otherwise the candidates are `[gen:<next>, ...leftover hand-written giants after last]`; return the first one that is not `skip`.
   The maker's mission comes first, so a solo child gets something to do at once.
3. `null` never happens any more after the 12 (there is always a `gen:<next>`); `left` and "You finished every mission!" go away
   (panel text, section 7).

- `give()`: as today; when the pick is `gen:n` and `state.seed == null`, set `state.seed = game.missionSeed()` first; store
  `spec = makeMission(n, seed)`; toast `Champion Solenne: ${INTRO[kind]}`.
- `swap()` from `gen:n`: `next = n + 1`, `spec = null`, then `nextMission(state, 'gen:' + n)` (a leftover giant, or `gen:n+1`).
  The skipped number is gone (no list to come back to). Swap from a hand-written mission: as today (its `last` logic), the
  candidates from rule 2 include `gen:next`. "This is the only mission left!" can no longer appear past the 9 solo ones.
- `complete(def)` for `gen:n`: `gen++`, `next = n + 1`, `active = null`, `spec = null`, `last = def.id`; hand-written: as today.
  The old "You finished every Champion mission!" toast + `celebrate()` stays, once, when the 12th hand-written one is done,
  worded `You finished all of Champion Solenne's missions! She has more for you!`. Every 6th generated mission done (end of a
  round) plays `celebrate()` with `Round ${r} done! The giants are getting bigger...`.
- `game.missionSeed()` (main.js, 1 line): `game.homeWorld?.seed ?? (game.world.realm ? <stashed main seed> : game.world.seed)`.
  The stashed seed is read through the existing realms API (`game.realms.mainPart()` / `stash`, read only; no edit to
  `realms.js`). Builder: check which one holds `seed` after T38a.

## 3. The maker (`src/missiongen.js`, pure, no `Math.random`, imports only data)

```js
export const ROUND = ['map', 'map', 'build', 'catch', 'rematchOrBuild']; // shuffled per round; 'boss' is always the 6th
export const FIRST_GEN = 13, ROUND_LEN = 6;
export const roundOf = n => Math.floor((n - FIRST_GEN) / ROUND_LEN) + 1;   // 13-18 -> 1, 19-24 -> 2 ...
export function makeMission(n, seed) -> { id: `gen:${n}`, n, round, kind, name, ...params }
```

- Random numbers: `mulberry32(((seed | 0) ^ 0x6d155e) + r * 7919)` for the round's order (Fisher-Yates over `ROUND`), and
  `mulberry32(((seed | 0) ^ 0x6d155f) + n * 104729)` for this mission's parameters. Both depend only on `(seed, n)`.
- Counting inside a round is closed form: the j-th map of all generated missions = `2 * (round - 1) + (maps before n in this round)`;
  the same for builds, catches, giants (one per round). No loop over earlier missions, no state.
- **map:** `{ kind: 'map', k: 5 + j % MORE_SPOTS, name: 'Treasure map ' + (6 + j) }` (j = generated map count before this one).
- **build:** `{ kind: 'build', build: { t, ...p }, name }` from a template (section 5); the template from the rand, never the same
  template twice in a row inside a round.
- **catch:** `{ kind: 'catch', type, name: `Catch a ${Type} creature` }`, type from `CATCH_TYPES` (below), not the type of the
  previous round's catch.
- **rematch:** `{ kind: 'rematch', gym, name: `${gymName} rematch` }`, gym from `REMATCH_GYMS` (below). `rematchOrBuild` is a
  rematch on even rounds, a build on odd rounds (so round 1 has 2 builds and no rematch: gentler start).
- **boss:** `{ kind: 'boss', boss: GIANT_CYCLE[(round - 1) % 3], grow: round, species, name: `Giant ${name}` }`,
  `GIANT_CYCLE = ['giant1', 'giant2', 'giant3']` (no new `BOSSES` entries in wave 13).
- **Pools (data, may grow later; the saved `spec` protects the active mission):**
  - `CATCH_TYPES`: types that live in main-world biomes with no special condition: fire, water, grass, electric, rock, bug,
    ice, sound, metal, mind, toxic, pixie, ghost, drake, sky, slime, light, paper, food, parkour. Not cozy / treasure (homes),
    dream (realm only), camo (disguised), cyber (needs a friend), cosmic / alien / bone (night or caves). The spec checks every
    entry has >= 2 species in `SPAWNS` main biomes with condition null/day/night (builder: drop any that fails).
  - `REMATCH_GYMS`: gyms with a building in the main world that are open all day and easy to reach: the first 16 minus night
    gyms (`def.night`), plus light, paper, food, squad. Not the Cozy Gym (home), Dream (realm), sky/cave gyms, Parkour (a long
    climb), Ninja. The spec checks every id is in `GYMS`, has no `night`, no `place`, no `realm`.

## 4. Treasure spots 6+ (`src/treasuremap.js`)

- `treasureSpots(world)` is **not changed** (the old five, cached on `world.treasureSpots`; `MAP_RULES`, `MAP_LEGS`, `MAP_GYMS` stay).
- New: `export const MORE_SPOTS = 24, MORE_GYMS = 32, MORE_RULES = { ...MAP_RULES, spread: 20, old: 16, tries: 300 }` and
  `moreTreasureSpots(world)` -> 24 spots (k 5..28), cached on `world.moreSpots`, and `spotOf(world, k)` = `k < 5 ?
  treasureSpots(world)[k] : moreTreasureSpots(world)[k - 5]` (missions.js and missionui.js use only `spotOf`).
- Same machinery as `findSpot` (copy the loop into a `findMore(world, k, chosen, out, rules)`; do not refactor the old one, so it
  cannot move): own rand `mulberry32((world.seed ^ 0x3c5a11) + k * 7919)`; legs cycle `MAP_LEGS` (k % 5); landmarks = the tower
  plus every gym of the first `MORE_GYMS` defs with `x != null`, `front`, not `sky`, not `place: 'cave'`, not `home`, not `realm`
  (slot gyms included: more places to start from); spread 20 from the other new spots and 16 from the old five; fallback as today.
- **Map area pinned to 288 x 368** (`WORLD_W`, `WORLD_D` values copied as constants `MORE_W/MORE_D`, so a later map growth never
  moves them); the edge rule uses them.
- **Keep-out (generic):** every `protect` box of every object in `[...world.gyms, world.tower]` (the same list `world.fenced` and
  `protectedAt` use) of the first `MORE_GYMS` gyms and the tower, Chebyshev gap 12 (relaxed 8); every sky gym `pad` (6); every
  `gymSlots()` box (also the empty spare slots 3 and 9: `world.gymSlots().map(s => s.box)`, 4). **The Portal Door (T38a):**
  T38a must put its protected box in `world.tower.protect` (or in an object of that list) so this rule covers it with no code
  here; the plan for T38a says it sits beside the tower door and is protected, so that is the natural place. Write this into
  the T38a/T38c merge note. Later main-world gyms must stay 12 blocks from `moreTreasureSpots()` too (CLAUDE.md line).
- Never in a realm: `update()` keeps today's `game.world.realm` pause; `moreTreasureSpots` throws on a realm world (like
  `legacyOnly`).
- Cost: 24 spots x at most 2 x 6 x 300 `okColumn` calls, done once on the first map mission past 12 (measure in the spec, < 200 ms
  on software rendering; else lower `tries`).
- `clueOf`, `drawMap`, `findCheck` work on any spot unchanged. The found rule (stand in the 2-deep hole) is the same.

## 6. Giants that grow (`src/coopboss.js`, `src/duel.js`, `src/battle.js`)

- `export const GROW = { level: 2, hp: 0.25, hpMax: 1.5 }`.
  `makeBoss(id, teamA, teamB, grow = 0)`: `cap = Math.min(REMATCH_CAP, 55 + GROW.level * grow)`,
  `level = Math.max(25, Math.min(cap, top + 2 + grow))`, `c.giant = b.giant + Math.min(GROW.hpMax, GROW.hp * grow)`.
  grow 0 gives today's numbers exactly (the coop spec's existing checks still pass). Round 1: cap 57, giant 3.25 (giant1);
  round 5: cap 65 = `REMATCH_CAP`, from then on only HP grows, until round 6 (+1.5) where it stops.
- The ask carries it: `coopFor` returns `{ mission, boss, at, grow }` (`grow` from the active def, 0 for hand-written);
  `duel.challenge` sends `coop.grow`; `cleanCoop` keeps it when it is an integer 0..99 (else 0); `battle.js` line with
  `makeBoss(this.coop.boss, this.allies, this.friends)` passes `this.coop.grow || 0`. Both browsers build the same giant.
- **Duel `VERSION` 11** (comment: `11: T38c giants grow (coop.grow)`). Draw order unchanged; no new draws.
- Helper: `coopEnded` uses `missionOf`; a helper whose own active mission is a boss still finishes it (as today, even if
  the boss or grow differ: "helping beats a giant" is the point). Rewards unchanged.
- Battle intro for grow > 0: `A giant ${name} appeared! It looks even bigger than last time!` (one more string, no logic).
- The model size stays `BOSS_SCALE` (a growing model could clip the camera; size is not worth the risk).
