## 0. What the owner asked for

> "parkour gym is too easy, we need it to be more difficult and tricky. you can borrow ideas from roblox games that have
> these types of mechanisms. for example not just jumping but jumping timing is also important. block you're standing on
> could disappear so you need to time it, or sth else pushes you out of it etc. in general it needs to be bigger / more
> difficult but still with somehow checkpoints (either current mechanism or floors ...). this should last at least 10 mins
> to fully finish. My son already played this one and even finished it (didn't fight the leader) but you can ignore his
> current checkpoints if they're saved."

Checkpoints are not saved today, so there is nothing to migrate. The player is a child who already beat the current
course: **harder, but fair**. Rules this plan keeps everywhere:

- **Readable:** every timed thing shows what it will do before it does it (a shake, a flash, a red warning look), and
  you can watch it from a safe spot (a platform or landing) before you try.
- **No blind jumps:** you always see where you land; nothing new appears in the air while you fly except a blink block
  you could see coming back (ghost outline, 5.2).
- **Never two timers at once on the same block:** a crumble block is never followed by a blink block (you could not
  wait on a crumbling block); the next piece after a crumble block is always a platform, a landing or another crumble.
- **Forgiving checkpoints:** 9 flags, never more than about 45 s of play between two of them.

## 2. Physics: what a child can jump (measured by simulation of `Player.update`)

Jump speed 8.6, gravity 28, walk 4.3, sprint 6.2 (Shift, or the touch stick pushed all the way), half-width 0.3.
"Air columns" = how many columns of air you can cross (horizontal flight minus the 0.6 you may hang over both edges).
Exact integration at 60 fps / the game's 20 fps clamp (`dt` 0.05, semi-implicit, lower apex):

| Takeoff | dy | 60 fps walk / sprint | 20 fps walk / sprint |
| --- | --- | --- | --- |
| normal jump (apex 1.25 / 1.11) | +1 | 1.26 / 2.09 | 1.12 / 1.88 |
| | 0 | 1.98 / 3.12 | 1.98 / 3.12 |
| | -1 | 2.41 / 3.74 | 2.41 / 3.74 |
| | -3 | 3.06 / 4.67 | 3.05 / 4.67 |
| | -5 / -8 | 3.63 / 5.50, 4.27 / 6.43 | 3.48 / 5.29, 4.34 / 6.53 |
| **spring** (`bounce: 4`: apex 3.88 / 3.63) | +3 | 2.77 / 4.26 | 2.62 / 4.05 |
| | +2 | 3.27 / 4.98 | 3.27 / 4.98 |
| | +1 / 0 | 3.63 / 5.50, 3.99 / 6.01 | 3.48 / 5.29, 3.91 / 5.91 |
| | -3 | 4.70 / 7.05 | 4.56 / 6.84 |

**Course rules (designed joins):** gap 0-1 anywhere; gap 2 only flat (twice: A3, G1); up 1 only with gap <= 1; spring
joins: up 3 with gap <= 1 (twice: H1, U1); no designed drops. **Landing pieces are at least 2 long in the jump
direction** (a walking gap-1 jump lands 2.6 past the takeoff, so a 1-long target is overshot), except up-1 targets
(T2, V6: an up-1 jump is short) and crumble bridge cells you walk onto. Beams always start next to the platform you stand on;
pushers sit at least one cell in from both beam ends.

**Skip rule (spec D2):** for any two pieces that are not consecutive, with `dist` = the Euclidean gap in columns between
their rectangles and `dy` = height difference, a jump is physically possible when `dist < reach(dy) + 0.3` (reach = the
60 fps sprint column above, the spring row if the first piece is a spring, `-1` = impossible for dy > 1 without a spring
and dy > 3 with one). Such a pair is allowed only inside one section or onto the very next flag's landing; **any pair that
reaches into a later section past its flag is an error**. The layout below passes (checked with the script in
Appendix A: 0 errors). The 14 allowed in-section shortcuts: cells of the crumble bridge reaching each other or L1
(you walk along it anyway), three-column running jumps over one small piece (C2->C4, P1->P2 over M2, V3->P4 over V4,
W2->P5 over W3) and SP2's spring straight onto beam P3 (skipping U1). None skips a flag.

and goes.", zap "A zap tile! Cross it when it is dark.", pusher "A pusher! Go when it pulls back.", spring "A spring!
Jump on it to fly up.", exit "Stand on it to go back down."

**Why not the T35 Bounce Block:** it has `bounce: 14` (a 14-block launch, made for half gravity) and is "never in the main
world" by rule; `fixed` is not needed (the protect box already refuses edits). `SPRING` is a course-only block with the
same `bounce` flag, so `Player.update` needs no change (it reads `BLOCKS[...].bounce` anywhere). Launch = **jump while
standing on it** (T35 rule, so walking over a spring never throws you); `main.js` already plays `boing` on `p.bounced`, and
`realms.onBounce()` / the realm hints only talk in a realm.

Every "live only" id is drawn with `world.setLive` (never an edit, never saved or sent). `noLight` on every glowing one,
so a flip never re-meshes the chunks around it (`GLOWS` skips `noLight`).

### 4.2 Pieces (data, copy literally)

Columns: `[id, d0, d1, s0, s1, h, kind, extra]`. Kinds and how they are built (top block at `P + h`):

- `plat`: two blocks thick, top `WOOL.parkour` with `WOOL.paper` edges, under it `WOOL.parkour` (as today).
- `beam`: one `BEAM` block. `extra.push = [[at, side, offset], ...]`: a pusher at position `at` along the beam (d for a beam
  along d, s for a beam along s), its body 2 columns to `side` (+1 = towards +s for a beam along d, towards +d for a beam
  along s): `PUSHER` at feet level and the one above (`P + h + 1`, `P + h + 2`); its head cells (1 column to `side`, same
  two heights) are air at build time. It pushes towards `-side`.
- `crumble`: one `CRUMBLE` block per cell. **Each crumble piece crumbles as one group.** (C4-C7 are four 1x1 pieces.)
- `blinkA` / `blinkB`: one `BLINK` block per cell; group A has offset 0, group B offset 2.0 (5.2).
- `zap`: like `plat`, but the top cells whose lane coordinate (s for pieces along s, d for pieces along d: the longer side)
  is inside a strip `[a0, a1]` of `extra.zap = [[a0, a1, offset]]` are `ZAP_OFF` (whole lane width). Its other top cells are
  plain wool (the safe cells).
- `spring`: like `plat`, but every top cell is `SPRING`.

### 5.1 Times (one exported object, so the owner can tune; all seconds)

```js
export const TIMES = {
  crumble: { shake: 0.9, gone: 3.0 },                  // shakes 0.9 s after your first step, then gone 3 s, then back
  blink: { cycle: 4.0, on: 2.0, warn: 0.8 },           // solid for on + warn (2.8 s), flashing in the last 0.8 s, then 1.2 s gone
  zap: { cycle: 3.0, off: 1.6, warn: 0.5 },            // dark 1.6 s, flashing 0.5 s (still safe), then on 0.9 s
  push: { cycle: 3.0, rest: 1.8, warn: 0.6, dist: 2.5, speed: 10 }, // out for 0.6 s; a shove moves you 2.5 blocks in 0.25 s
};
const phase = (t, offset, cycle) => (((t - offset) % cycle) + cycle) % cycle;
export const blinkState = (t, off) => { const p = phase(t, off, 4.0); return p < 2.0 ? 'on' : p < 2.8 ? 'warn' : 'off'; };
export const zapState = (t, off) => { const p = phase(t, off, 3.0); return p < 1.6 ? 'off' : p < 2.1 ? 'warn' : 'on'; };
export const pushState = (t, off) => { const p = phase(t, off, 3.0); return p < 1.8 ? 'rest' : p < 2.4 ? 'warn' : 'out'; };
export const crumbleState = (t, at) => at == null ? 'whole' : t - at < 0.9 ? 'shake' : t - at < 3.9 ? 'gone' : 'whole';
```

(Write them with `TIMES` fields, not literals.) Blocks per state: blink on `BLINK`, warn `BLINK_WARN`, off `AIR`; zap off
`ZAP_OFF`, warn `ZAP_WARN`, on `ZAP_ON`; pusher rest: body `PUSHER`, head `AIR`; warn: body `PUSHER_WARN`, head `AIR`;
out: body `PUSHER`, head `PUSHER_HEAD`; crumble whole `CRUMBLE`, shake `CRUMBLE_SHAKE`, gone `AIR` (when `crumbleState`
returns to whole, `crumbleAt` is deleted).

### 5.2 The mechanics, one by one (what the child sees, the window, why it is fair)

1. **Crumble blocks** (S1, then T2, D1, V6, W2). Step on one: it cracks (`CRUMBLE_SHAKE`, sound `crumble`), 0.9 s later
   it is gone, 3 s later it is back. The trigger is the **footprint**: any of the up to 4 cells under the corners of
   your box (`x +- 0.3, z +- 0.3` at `floor(y - 0.05)`) while on the ground, so standing on an edge also counts. A walking
   2-long crumble takes 0.47 s to cross, the 4-cell bridge 0.93 s (each cell has its own 0.9 s), so walking on never
   fails and stopping always does. Comes back with `LiveCells` (never inside a player).
2. **Blink blocks** (S2, then K6/K7, V2/V3, W1, W5). Two groups take turns on a 4 s cycle: A is solid for t in [0, 2.8)
   (flashing in [2.0, 2.8)), B for [2.0, 4.8) (flashing in [4.0, 4.8)). **When yours flashes, the next one is there**:
   the overlap is 0.8 s, and with 0.46-0.61 s of flight you can leave A any time from about 1.4 s (B appears at 2.0) to
   2.8 s: a 1.2-1.4 s window every 4 s. Both groups are drawn with a **ghost outline** while gone (one `THREE.LineSegments`
   for all blink cells, white, opacity 0.35, built in the constructor from `gym.ghost`, removed in `dispose()`; always
   shown: it sits on the block's edges when the block is there), so you see where the block will come back.
3. **Zap tiles** (S3, then Z3, V5, W4). A strip (3 wide, 3-4 deep) is dark for 1.6 s, flashes for 0.5 s (still safe),
   then is on for 0.9 s. Standing on `ZAP_ON` (the cell under your centre, the `stand` hook, so it is lenient at the
   edges) = sound `zap`, back to your flag. A 4-deep strip takes 0.93 s walking (0.65 s running): you are safe if you
   start within about the first 1.2 s of the dark time, about 39% of the cycle; you can always wait on the wool before it.
   Z1's two strips are 1.5 s apart with a 2-cell island between, so you can rest in the middle. Jumping over a 3-4 deep
   strip with a running jump is allowed (a stand is only counted on the ground).
4. **Pushers** (S4, then P3, P4, P5). A metal box beside a beam: rests 1.8 s, flashes red 0.6 s, then punches out (its
   head appears between it and the beam) for 0.6 s. While it is out, if your box overlaps the beam cell in front of it
   (feet level and the cell above), you are **shoved**: 2.5 blocks away from the pusher in 0.25 s, applied by
   `CourseLive.update` with `player.moveAxis(axis, sign * step)` after `p.update` (so walls stop it, and holding the stick
   back cannot win: you move at most 1.1 blocks in 0.25 s). You fall off the beam (sound `whoosh`). The head cells are
   never in the beam column, so `LiveCells` never has to wait for them. **A pusher is never on a beam's first or last
   cell** (standing on the platform's edge your box already overlaps the first beam cell). On a beam with more pushers the
   next one you meet punches 2.5 s after the first (P5's third with the first): so the readable rule **"go right after the
   first pusher pulls back"** gets you across every time (checked for start delays 0-0.3 s, walking). Nonstop walking at a
   random moment succeeds for about 68% of start times on P1 (one pusher) and 36% on P2-P5 (45-72% running), so timing
   matters (spec D5 measures these windows).
5. **Springs** (SP1, SP2). Jump while standing on one: you fly about 3.9 blocks up (3.6 at 20 fps) and land on a platform
   3 up with 1 column of air between. Sound `boing` (already played by `main.js`).
6. **Exit Pad** (on F). Stand on it: you are placed at `gym.exit` (ground, by the entrance), facing away, sound `whoosh`,
   toast "Great run! Come back any time." (badge held) or "Back on the ground. Your flag waits for you!" (no badge).
   Coming back up the stairs onto S0 takes you to your flag (5.6), so a rematch with the leader is quick.

### 5.3 Active range (cheap and fair)

Only elements near the player animate: an element is **active** when the player is within `activeR` = 14 columns
(Chebyshev in x/z) of the element's middle and within 7 blocks of its top in y. Inactive elements show their rest state
(blink on, zap off, pusher rest, crumble whole; a crumble that is already counting finishes its cycle wherever you are).
When an element becomes active it jumps straight to its closed-form state. This keeps the number of block flips (each one
re-meshes one 16x16 chunk) to the 4-8 elements around you: about 4-8 flips a second, never the whole course.
Every element's state is cached and a block is written only when its state changes.

### 5.4 `update(dt)` order (called every frame by `gymLive.update`, after `p.update`)

1. `clock += dt`.
2. If a shove is running: move the player (`step = min(left, speed * dt)`), stop when `left <= 0` or `p.hitWall`.
3. For every element: state = active ? closed form : rest; if it changed, `cells.want(...)` for its cells; then
   `cells.flush()`.
4. If `game.inBattle`, stop here (no rules during battles). If `p.onGround`: footprint cells (the up to 4 cells under
   your box's corners) -> start any crumble
   piece under you that is not counting (`crumbleAt.set(id, clock)`, sound `crumble`); then the **earlier-section
   catch** (5.6).
5. Pushers that are `out`: if the player overlaps one's zone and no shove is running: start a shove, sound `whoosh`.
6. Flags drawn lit (as today, `draw()`).
7. Remember `wasAir = !p.onGround`, and `lastTop` = the top under you while on the ground (for the next frame's catch).

### 5.5 `stand(x, y, z, id)` (unchanged hook, called after `update` while on the ground)

In this order: a flag cell -> the flag logic (below); `EXIT_PAD` on F -> exit (5.2.6); `ZAP_ON` -> `sendBack('zap')`;
`SOFT_MAT` inside `course` -> `sendBack('fall')` (as today). Flag logic: as today, plus the once-per-session hint
(`game.toldOnce` key `course:<k>`): a new flag `k > reached` toasts `Checkpoint! ${hint}` + ` ${trainer} wants to battle
you!` when its trainer is not beaten; CP0 (never "new") toasts its hint the first time you stand on it. The old
"Your flag is waiting! Hop onto the soft mat..." toast goes (5.6 does it).

### 5.6 Sending back

`sendBack(why)`: `k = target()` (unchanged: the furthest reached flag, never past an unbeaten trainer's landing), player
to `checkpoints[k].stand`, `vel` 0, `yaw` = its yaw, pitch 0, `shove = null`, `falls++` (`zaps++` too for a zap),
sound `boing` (`zap` for a zap), toast:

| why | k = 0 | k > 0 |
| --- | --- | --- |
| `fall` (mat, rim, or an earlier piece) | Boing! Back to the start. | Boing! Back to your last flag. |
| `zap` | Zap! Back to the start. | Zap! Back to your last flag. |
| `start` (you stepped on S0 while your flag is further) | (never) | Your flag is waiting! Whoosh! |

**Earlier-section catch** (5.4 step 4): `e = secAt.get(key of the cell under your centre)` (the block `stand` would get).
Send back when `e.sec < target()` and either **you just landed from a fall** (on the ground now, in the air last frame,
and this top is at least 2 below the last top you stood on: `CourseLive` keeps `lastTop` and `wasAir`) -> `why = 'fall'`,
or **`e.start`** (any time on S0) -> `why = 'start'`. Walking back onto the previous piece next to a landing is not a
fall and does nothing (no surprise teleports at the edge of a landing). Same section or later: nothing (a fall inside a
section onto a lower piece of the same section is just a retry from there; the layout keeps those rare).

Never caught: the stairs, the ground outside, pusher-free beams' surroundings (not in `secAt`). A fall onto the ground
outside the rim is "leaving"; walking back up to S0 takes you to your flag.

### 5.7 `prompt(block)`

`'Checkpoint flag'` on a flag, `'Exit pad · stand on it to go down'` on `EXIT_PAD`, else null. No `hit`.
`dispose()`: remove and free the ghost outline. No other method names (the `gymLive` hook rule).

Multiplayer: everything is per player (like the Firewall Maze lasers): a friend sees their own blink and zap timing,
so on your screen a friend may stand "on air" for a moment. Nothing is sent. (Shared timing is backlog S1-S2 material.)

## Appendix A: the layout checker (port into D2; it ran on the data above with 0 errors)

```js
// pieces = PIECES as objects { id, d0, d1, s0, s1, h, kind, x, i, sec } (sec = index of the flag piece before it)
const gapOf = (a, b) => ({ gd: Math.max(0, b.d0 - a.d1 - 1, a.d0 - b.d1 - 1), gs: Math.max(0, b.s0 - a.s1 - 1, a.s0 - b.s1 - 1) });
const NORMAL = { 1: 2.09, 0: 3.12, '-1': 3.74, '-2': 4.26, '-3': 4.67, '-4': 5.1, '-5': 5.5, '-6': 5.8, '-7': 6.1, '-8': 6.43 };
const SPRING = { 3: 4.26, 2: 4.98, 1: 5.5, 0: 6.01, '-1': 6.32, '-2': 6.74, '-3': 7.05, '-4': 7.4, '-5': 7.67, '-6': 8, '-7': 8.4, '-8': 8.7 };
const reach = (dy, spring) => spring ? (dy > 3 ? -1 : SPRING[Math.max(dy, -8)]) : (dy > 1 ? -1 : NORMAL[Math.max(dy, -8)]);
for (const a of pieces) for (const b of pieces) {
  if (b.i <= a.i + 1) continue;                                   // consecutive or backwards: fine
  const { gd, gs } = gapOf(a, b), r = reach(b.h - a.h, a.kind === 'spring');
  if (r < 0 || Math.hypot(gd, gs) >= r + 0.3) continue;            // cannot be jumped
  const skipsAFlag = b.sec > a.sec && !(b.sec === a.sec + 1 && FLAG_PIECES.includes(b.id));
  if (skipsAFlag) error(`${a.id} -> ${b.id}`);                     // into a later section past its flag
}
// joins: for consecutive a, b: straight (gd === 0 && gs === 0 and they overlap on one axis, or a gap on one axis with
// overlap on the other); spring: dy <= 3 and gap <= 1; else dy <= 1 and (gap <= 1 or gap === 2 && dy <= 0)
// headroom: every top cell has air at h + 1 .. h + 4 (h + 6 over springs), pieces 2 thick except beam/crumble/blink
// pushers: body at 2 columns to `side` (feet level and +1), head at 1 column; `at` not a beam end; the 4 columns on the
// push side (-side), from the mat up to beam top + 2, hold no cell of a piece whose sec >= the beam's sec
```
