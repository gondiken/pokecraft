# T18 · Three new types: Time, Camo, Cyber (plan)

Owner's design (ROADMAP "Waves 7 and 8", T18): each new type has **its own special way to be found**, written as
**spawn conditions as data**, not one code path per type. Time only in a short sunrise/sunset window, Camo looks
exactly like the local block and blinks, Cyber only when two players are close. **No new battle mechanics.**

Result: **26 types**, 107 → **123 moves** (+13 type moves, +3 signature moves), **182 normal species** (26 × 7,
+21) + Zenithar, 14 signature moves, 3 new wool blocks (ids **54-56**), 12 new body shapes, two new modules
(`src/spawnrules.js`, `src/disguise.js`). Ids below are final; T19 (gyms) and T21 (home condition) rely on them.

Parallel tasks (wave 7a): **T16** owns `src/guide.js` (+ maybe a few lines of `main.js`), **T17** owns `world.js`,
`gymplace.js`, `multiplayer.js` (`WORLD_VERSION`), the map size and break/place protection in `main.js`
(`breakBlock`/`placeBlock`). T18 **never edits** `world.js`, `gymplace.js`, `guide.js`, `multiplayer.js`, `npc.js`,
`gyms.js`. Unavoidable overlaps: `main.js` (5 small hunks, listed in §8, none inside `breakBlock`/`placeBlock`),
`CLAUDE.md`/`README.md` (separate paragraphs; "keep both" at merge), possibly `blocks.js` if T17 adds a block
(T18 takes ids 54-56; anyone else takes 57+).

## 6. Spawn conditions as data (`src/spawnrules.js`, new) and disguises (`src/disguise.js`, new)

### 6.1 `spawnrules.js`
```js
// Spawn conditions: the third entry of a SPAWNS entry names one. A condition is plain data plus a test,
// so new ways to be found (T21: near a home of type X) are one more entry here, not new code paths.
//   ok(ctx, arg)   is the condition true now?    share  with ok, this fraction of spawn attempts comes from
//   max            at most this many alive at once (per player)   text  words for the Book   toast  shown on spawn
export const GOLDEN = 60 / 480; // one minute of the 8-minute day, centred on sunrise (time 0) and sunset (0.5)
export function goldenHour(time) { const t = ((time % 1) + 1) % 1; return t < GOLDEN / 2 || t >= 1 - GOLDEN / 2 ? 'dawn' : Math.abs(t - 0.5) < GOLDEN / 2 ? 'dusk' : null; }
export const TOGETHER_RANGE = 30;
export const CONDITIONS = {
  day:   { ok: c => !c.night, text: 'day' },
  night: { ok: c => c.night, text: 'night' },
  dawn:  { ok: c => c.golden === 'dawn', share: 0.4, max: 3, text: 'at sunrise' },
  dusk:  { ok: c => c.golden === 'dusk', share: 0.4, max: 3, text: 'at sunset' },
  together: { ok: c => c.friendsNear, share: 1 / 15, max: 1, text: 'with a friend close by',
    toast: 'Bzzt! Playing together woke up a cyber creature nearby!' },
};
// 'name' or 'name:arg' (T21: 'home:cozy').
export const condOf = s => (s ? CONDITIONS[s.split(':')[0]] : null);
export const condOk = (s, ctx) => !s || !!condOf(s)?.ok(ctx, s.split(':')[1]);
```
`game.time` 0 = 06:00, so dawn is 04:30-07:30 and dusk 16:30-19:30 on the HUD clock (the day/night switch at
light 0.3 falls inside each window, at about 05:50 and 18:10). For T21: add `home: { ok: (c, type) =>
c.homes.some(h => h.type === type), share: ..., max: 1, text: ... }` and `homes` to the context; nothing else.

### 6.2 The context and the generic pick (in `creatures.js`)
- New field `this.env = null` (set by main.js, §8): `{ time: () => number, friends: () => Vector3[] }`.
- `context(playerPos, night, under)` → `{ night, under, golden: under ? null : goldenHour(env.time()), friendsNear:
  env.friends().some(p => Math.hypot(p.x - playerPos.x, p.z - playerPos.z) <= TOGETHER_RANGE) }` (no env →
  `golden: null, friendsNear: false`). A helper `asCtx(x)` turns the old boolean `night` argument into
  `{ night: x }` so `weights(b, night)`, `pickEntry(b, night)`, `pickSpecies(b, night)`, `trySpawn(c, s, night)`
  keep working for the existing specs.
- `weights(biome, ctx)`: entries whose condition is ok **and has no `share`**, with the weather boost (unchanged
  output for today's tables).
- `pickEntry(biome, ctx)`:
  1. For each distinct `share` condition among this biome's entries (in table order): skip it unless `condOk` and
     `this.count(cond) < max`; then with probability `share` do a weighted pick among those entries (weather boost
     applied too) and return `[species, cond]`.
  2. Otherwise the weighted pick from `weights(biome, ctx)`, as today.
  `count(cond)` = `this.list.filter(w => w.when === cond).length`.
- `wild.when` stays the field name and now holds any condition string (the `blocks` spec reads `c.when === 'day'`).
- The leaving rule becomes generic: `wrongTime = !condOk(w.when, ctx) || !!w.cave !== under` (same distances as now),
  so Time creatures leave when their window closes and Cyber ones when the friend walks away or leaves the world.
- `update(dt, playerPos, spawnPoint, night, under)` builds `ctx` once per spawn tick and passes it to
  `trySpawn`/`trySpawnCave`. Also remembers `this.viewer = playerPos` for blinks.
- `onSpawn` gets the wild as today; main.js shows `condOf(wild.when)?.toast` (generic, §8).

### 6.3 `disguise.js`: "Camo creatures wear a disguise"
One small class, reused by T19's Hidden Hill trainers (stone pillars: `new Disguise(world, B.STONE, { w: 1, h: 2 })`).
```js
export class Disguise {
  constructor(world, block, { w = 1, h = w } = {})  // a w×h×w box of `block`, min corner at local (-w/2, 0, -w/2)
  group            // THREE.Group: the block faces (world.materials.solid, shared) + an eyes group (hidden)
  blinkIn          // seconds to the next blink: 22-38 (about twice a minute); the first one 3-30
  update(dt, viewerPos)  // counts down; a blink shows the eyes on the face that looks most towards the viewer
                   // for 0.25 s, then a closed-eye line for 0.1 s, then hides them again
  blink(viewerPos) // starts a blink now (tests)
  get blinking()   // true while eyes or the closed line show
  dispose()        // removes the group, disposes its geometries and its OWN eye materials; never the shared
                   // world material
  static pick(world, x, y, z, blocks)  // the candidate block found most often in x±4, y-3..y+6, z±4; null if < 3
  static fits(world, x, y, z, w, h)    // every column in the w×w footprint: solid below y, air from y to y+h-1
}
```
**Looks exactly like the world**: the geometry is built like `World.buildChunk` faces: per face the atlas tile
(`BLOCKS[block].top/side/bottom`, uv as in `World.addFace`: `(tile + (u ? 0.999 : 0.001)) / TILE_COUNT`), vertex
colour `r = shade × world.skyAt(neighbour cell)`, `g = shade × blockLight`, `b = shade`, with the same shades
(top 1.0, ±x 0.62, ±z 0.45, bottom 0.32; copy the 6 numbers, don't import from world.js). `blockLight` = max over
glow blocks within 4 (Manhattan) of `0.9 - 0.18 × distance` (same formula as `World.stampLight`), computed once.
Material = `world.materials.solid` (texture, alphaTest for see-through leaves, cave/day-night shader). A 2×2×2
disguise is one big cube whose faces repeat the tile 2× (4 quads per face), so it reads as 8 blocks. The face
colours are computed once at spawn (light changes while it sits there are fine). Eyes: `MeshBasicMaterial` boxes
(white 0.16×0.14 with a black 0.08 pupil, 0.25 apart, at 60% height, 0.005 in front of the face), closed = a dark
0.2×0.03 line each.

### 6.4 Camo behaviour (in `creatures.js`)
- `spawnAt(species, x, y, z, { when, cave } = {})` (new, public; used by `trySpawn`, `trySpawnCave` and the
  tests): builds the model and the `Wild` as today. If `SPECIES[species].disguise`:
  `size = d.size || 1`; `if (!Disguise.fits(world, x, y, z, size, size)) return null`;
  `block = Disguise.pick(world, x, y, z, d.blocks)`; null → return null (no spawn, try again next tick).
  Then `wild.disguise = new Disguise(world, block, { w: size })`, added to `wild.model`; the real model's
  `parts.root.visible = false`; `wild.pos = (x + size/2, y, z + size/2)`, `heading = 0`.
- `trySpawn`: for a disguised species call `spawnAt(species, x, groundY, z)` with the integer cell just above the
  ground (`groundY` = `surface.y + 1`, as `groundY()` returns today); `trySpawnCave` the same with its floor `y`.
  `spawnAt` returning null just means "no spawn this tick".
- `Wild.still` = `!!species.disguise`: Camo creatures never walk (also after popping out; they idle in place).
- `updateOne`: a disguised wild only counts `t`/`life`, calls `disguise.update(dt, this.viewer)`, keeps
  `model.rotation.y = 0` and does **not** call `animateModel` (the real model is hidden). No wiggle, no sound.
- `Wild.reveal()`: if disguised, remove and dispose the disguise, show `parts.root`, start a 0.3 s pop (`popT`:
  root scale 0.3 → 1.1 → 1, done in `updateOne`'s frozen path too), play `sound.play('popout')`, return the block
  name (`BLOCKS[block].name`); else return null.
- `remove(w)`: `w.disguise?.dispose()` **before** `disposeModel(w.model)` (disposeModel would dispose the shared
  world material).
- Bumping: in `update`, a disguised wild whose box the player walks into (`|dx|, |dz| < size/2 + 0.4`,
  `0 <= playerPos.y - pos.y < size + 1`) calls `this.onBump?.(w)` once (main.js starts the battle). Kids walking
  "through" a block would otherwise find it by accident in a confusing way.
- Never changes the world (`world.set` is never called), never saved, never sent: wild creatures are per player
  already.
- The name tag needs nothing new: `creatures.pick` raycasts the disguise mesh, so looking straight at one shows
  "Bushling Lv 5 · click or E to battle" like any creature. Hitting it (left click = `interact()` first) or tapping
  it (`tapAt`) starts the battle.
