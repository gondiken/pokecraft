# T33 · Food type and the Restaurant gym (plan)

Owner's design: ROADMAP "Wave 11 · T33 · 🍎 Food". Shared wave decisions: `plans/wave11.md` (read it first: step 0 is
already on the branch: `food` in `TYPE_COLORS`, the chart row/column, wool **79**). This task adds:

- **7 Food creatures** (funny dishes with faces): a sushi family, a burger family, a spaghetti family and a single ice
  cream cone; **4 new body shapes**; normal biome spawns near where their food "comes from".
- **Moves:** 4 type moves (`T1`-`T4`), 1 signature move, 3 big moves (rally, sacrifice, field), fx + `fx:food`.
- **The Restaurant** (gym 28, south slot 5): two trainers, four customers at numbered tables, **Chef Basil** (the
  leader) gives an order, you find the ingredients out in the world, cook them in a pot (tap while golden), serve the
  dish to the customer, and their happy line opens the Chef battle. Each rematch is the next dish on the menu.
- **Blocks 83-86** (Cooking Pot, Golden Pot, Burnt Pot, Stove), `WORLD_VERSION` 12 -> **13**.

Custom code stays small, exactly the roadmap's three pieces: (1) ingredients from breaking natural blocks (one generic
hook in `breakBlock`), (2) the pot (one live object, `RestaurantLive`, about the size of `VaultLive`), (3) the menu
table (data in the gym def). Everything else is reused: `game.keys` (saved, `loadKeys`), `gymLive`/`LiveCells`/
`setLive`, `SLOT_BUILDERS`/`levelSite`, NPCs, T28 rematches, access pieces.

**Files:** new `src/restaurant.js`; small hooks in `main.js`, `gymlive.js`, `rematch.js`, `npc.js`, `access.js`,
`gymplace.js` (one line); data in `species.js`, `shapes.js`, `fxrecipes.js`, `sound.js`, `gyms.js`, `blocks.js`;
`multiplayer.js` (`WORLD_VERSION`); specs; README, CLAUDE.md. Keep every edit to shared files in its own appended
section or a single own line (wave11.md "Files each task owns"), so the orchestrator's merge is "keep both".

## 0. Facts the design relies on (checked in the code)

- `game.keys` (main.js) is a per-player list of `'<gymId>:<key>'` strings, saved as `keys`; `loadKeys` keeps only
  strings named in some `def.keys` (`ALL_KEYS`). Only `WHEN.keys` (access.js) and `VaultLive` read `def.keys`, and
  `WHEN.keys` is used only by gyms with `access.when === 'keys'`. So a gym may list any keys in `def.keys` without
  being "locked". **No new save field is needed.**
- `breakBlock` (main.js) computes `natural = !world.edits.has(index)` before breaking; `hit.id` still holds the
  broken block's id afterwards. `world.set(x, y, z, id, false)` writes a block without an edit (= natural), which
  the spec uses to put test blocks anywhere (world independent).
- `breakBlock`, `interact()` (click/E/touch action) and `tapAt` all call `game.gymLive.hit(block)` first, so a
  click, a tap or the touch break button on the pot reaches the live object; protected blocks never break.
- `talkTo` (main.js): healer, tower, `closedText`, disguise reveal, trainers (`trainersOf`/`trainerKey`), the
  "Beat X and Y first" refusal, then leader -> `game.rematch.offer(npc)` (badge held) or the badge battle.
  `onBattleEnd` handles trainer wins, `opts.rematch` -> `game.rematch.won`, badge wins.
- `createGymLive(game)` makes one object per gym with `def.live` (`LIVE[kind]`), per world (`reset(world)` in
  `createWorld`), so in a realm (no gyms) there is no Restaurant object: no ingredients while dreaming (fine).
- Slot gyms: `placeSlotGyms` calls `SLOT_BUILDERS[def.build](world, def, slot)`; slot 5 = `southSlots()[0]`, the
  south slot nearest the start, centre z 314..340, box = centre +-24 (`SLOT_R`). The door faces the middle of the
  map with the same `front` rule as `buildTreasureVault`.
- `NpcManager.populate` makes the leader (`look: leader.look`), the trainers (`gym.trainerPositions`,
  `gym.trainerHeadings`) and nothing else per gym. `Npc.title` is `"<name> (<gym name>)"`.
- `animateModel`: `parts.wobble` entries set `rotation[axis] = sin(t*speed+phase)*amp` (absolute, not added);
  `parts.spin`, `parts.bounce` (+ `hover`), `legs`, `arms`, `head`, `tail` as before. Helpers in shapes.js: `box`,
  `pivot`, `eyes`, `glow`, `ball`, `zigzag`, and the module-level `has`, `swing`, `spin`, `mouth`.
- `frame()` caps `dt` at 0.05 s, so at 1-2 fps (software rendering in tests) dt-based timers run 10-40x slow. The pot
  therefore uses **real time** (`performance.now()`) and judges a tap **at the moment of the tap**.
- `REACH` is 6 blocks (main.js).

### 6.3 The pot, orders and serving — `RestaurantLive` (`LIVE.restaurant`)

In `gymlive.js`: import it and one own line `LIVE.restaurant = RestaurantLive; // T33` after the `LIVE` const. Four

(A live object must not use these four names for anything else, the same rule as `stand`/`hit`/`prompt`.)

**Pure helpers** exported from restaurant.js (used by the live object, `WHEN.menu` and the spec):
```js
// Which dish is on the menu for this player: the badge dish first, then one more per rematch win (1..n-1, round again).
export function dishIndex(game, def) {
  if (!game.badges.includes(def.id)) return 0;
  return 1 + ((game.rematchWins[def.id] || 0) % (def.menu.length - 1));
}
// The open order: stage 'none' | 'shopping' (ingredients missing) | 'cook' (all found) | 'cooked' (dish ready) | 'served'.
export function orderState(game, def) {
  const has = k => game.keys.includes(`${def.id}:${k}`);
  const i = dishIndex(game, def), dish = def.menu[i];
  const missing = dish.ingredients.filter(k => !has(k));
  const stage = has('served') ? 'served' : has('cooked') ? 'cooked' : has('order') ? (missing.length ? 'shopping' : 'cook') : 'none';
  return { i, dish, missing, stage };
}
// The guide's words for the open order (WHEN.menu status), '' without one.
export function menuStatus(game, g) {
  const def = g.def, s = orderState(game, def), d = s.dish, I = def.ingredients;
  if (s.stage === 'none') return '';
  if (s.stage === 'served') return ` · ${def.leader.name} is waiting for a battle`;
  if (s.stage === 'cooked') return ` · ${d.emoji} ${d.name} is ready: take it to table ${d.table}`;
  if (s.stage === 'cook') return ` · ${d.emoji} ${d.name}: cook it in the pot!`;
  return ` · ${d.emoji} ${d.name}: ${d.ingredients.map(k => I[k].emoji + (s.missing.includes(k) ? '' : '✓')).join(' ')}`;
}
```
`table` words everywhere: `table ${n} (${color})`, e.g. "table 2 (blue)" (the colours come from `gym.tables`).

**State and saving** (exactly this, nothing else):
- In `game.keys` (saved with every `game.save()`): `food:order` (an order is open for dish `dishIndex`),
  `food:cooked` (you hold the finished dish), `food:served` (served; the Chef battle is waiting), and one
  `food:<ingredient>` per ingredient found (**kept forever**: "ingredients already found still count").
- The dish is never saved: it follows from `badges` + `rematchWins.food`, which only change when the Chef battle
  is won, and that is exactly when `order`/`cooked`/`served` are removed.
- Not saved: the cooking in progress (`cookAt`). After a reload the pot is idle and you tap it again.
- `served` without `cooked` or `cooked` without `order` (an edited save) still work: the stage is the highest one.

**The live object** (constructor `(game, gym)`; `this.cells = new LiveCells(game.world, () => game.player)`;
`this.now = () => performance.now() / 1000` (tests replace it); `this.cookAt = null`; `this.last = 'idle'`):
- `RAW = 3` s, then golden for `dish.time` s, then burnt for `BURNT_SHOW = 2.5` s, then idle again.
- `phase(now)`: `cookAt == null` -> `'idle'`; `t = now - cookAt`; `t < RAW` -> `'raw'`; `t < RAW + time` ->
  `'golden'`; `t < RAW + time + BURNT_SHOW` -> `'burnt'`; else `'done'`.
- `update(dt)`: `cells.flush()`; `p = phase(now())`. If `p === 'done'`: `cookAt = null`, `p = 'idle'`. On a change
  from `this.last` (only toast when the player is within 16 blocks of the pot): `'golden'` -> `sound.play('cookding')`,
  toast "It's golden! Tap the pot now!"; `'burnt'` -> `sound.play('potburnt')`, toast "Oh no, it burnt! Tap the pot to
  try again. Your ingredients are safe." Then `cells.want(...gym.pot, p === 'golden' ? B.POT_GOLDEN : p === 'burnt' ?
  B.POT_BURNT : B.POT)`; `this.last = p`. Cheap per frame (`want` returns at once when nothing changes).
- `hit(block)`: `false` unless `block` is at `gym.pot`. Then by `orderState` and `phase(now())` **at the time of the
  tap** (one toast each, kid words):
  - stage `none`: "Talk to Chef Basil first. He will tell you what to cook!"
  - `shopping`: "You still need 🍯 🌰 for Berry Pie." (the missing emojis)
  - `cooked` / `served`: "The Berry Pie is ready! Take it to table 2 (blue)." / "Go and battle Chef Basil!"
  - `cook` and idle: `cookAt = now()`, `sound.play('potbubble')`, "Watch the pot! Tap it when it turns golden."
  - `cook` and raw: "Not yet... wait until it turns golden!" (no penalty)
  - `cook` and golden: push `food:cooked`, `cookAt = null`, `sound.play('yum')`, "🥧 Berry Pie is ready! Take it to
    table 2 (blue).", `game.save()`.
  - `cook` and burnt: start again at once (`cookAt = now()`, `potbubble`, "Let's try again! Tap it when it turns golden.").
  Always `return true` for the pot (it never breaks).
- `prompt(block, how)`: at the pot: golden -> `Cooking pot · it's golden, ${how} now!`; otherwise
  `Cooking pot · ${how} to cook`. (The touch button says "Press!", the generic gym word.)
- `broke(block)`: only in stage `shopping`; find the first missing ingredient whose `blocks` (names -> `B[name]`)
  include `block.id`; push `food:<id>`, `sound.play('keyfound')`, toast "🫐 You found a berry! (2/3 for Berry Pie)";
  when none is missing any more, a second toast "You have everything for Berry Pie! Cook it in the pot at the
  Restaurant."; `game.save()`. Nothing for other blocks, other stages, or an ingredient you already have.
- `talk(npc)`: `false` unless `npc.gym === this.gym`.
  - **Chef** (`kind === 'leader'`): if not every trainer is beaten (`trainersOf(def).every((p, i) =>
    game.beaten.includes(trainerKey(def, i)))`) return `false` (the normal "Beat Waiter Olive and Cook Benny first"
    refusal runs). Else by stage:
    - `none`: push `food:order`, `game.save()`, toasts "Chef Basil: Table 2 (blue) wants Berry Pie! I need 🫐 🍯 🌰."
      and "Find them out in the world: 🫐 tree leaves · 🍯 flower bushes in meadows · 🌰 pine trees where it is
      cold. Break one of each!" (only the missing ones; if none is missing: "You already have everything. Cook it in
      the pot!").
    - `shopping`: "Chef Basil: Berry Pie for table 2 (blue). Still missing: 🍯 🌰. Look in flower bushes and pine trees."
    - `cook`: "Chef Basil: You have everything! Cook it in the pot. Tap the pot when it turns golden."
    - `cooked`: "Chef Basil: Quick, take the Berry Pie to table 2 (blue) before it gets cold!"
    - `served`: start the Chef battle again (`startChef()`, below): losing never costs you the dish.
    Return `true`.
  - **Customer** (`kind === 'guest'`): if stage `cooked` and `npc.def.table === dish.table`: push `food:served`,
    remove `food:cooked`, `sound.play('yum')`, toast `${npc.name}: Yum, ${dish.name}! Thank you! Chef Basil, come and
    see!`, `game.save()`, then `startChef()`. Else if the order is open (`shopping`/`cook`) and it is their table:
    `${npc.name}: Is my ${dish.name} coming? I can't wait!`. Otherwise return `false` (main.js shows their own line).
- `startChef()`: `chef = game.npcs.list.find(n => n.gym === this.gym && n.kind === 'leader')`. Without the badge:
  the normal badge battle `game.startBattle({ trainer: chef, team: def.leaderTeam, intro: def.intro })`. With the
