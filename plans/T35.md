Status: ready to build (open questions at the end each have a default, so no builder waits on them).

Read first: `ROADMAP.md` "Wave 11" (T35 bullets = owner decisions), `plans/wave11.md` (shared ids, chart, levels, file
ownership), `plans/T31.md` (realms), `plans/wave11-prototypes/proto.html` (builders `headstander`, `toddler`,

**In one line:** Dream gets 7 creatures that look "held together by nothing", its own moves and fx; the Dream realm grows
to a 256 x 256 sky of floating islands with moon-jump gravity and bounce blocks; and the first gym that lives inside a
realm, the **Upside-Down House**, with a healer, a moon on the HUD and a friendly morning.

Nothing in the main world's blocks changes (`old-saves` / `big-map` / `caves` checksums unchanged, no `WORLD_VERSION`
bump). Dream creatures spawn only in the Dream realm.

## 1. Step A: the type

### 1.1 The type look: "held together by nothing"

Every Dream creature's parts (head, body, legs, ears, tail, balloon...) float a little apart (gap `DRIFT_GAP = 0.15`)
and each bobs on its own. Generic, no type check anywhere:

- `shapes.js` (T35 section) exports `DRIFT_GAP` and
  `drift(parts, g, amp = 0.05, speed = 1.6, phase = 0)`: pushes `{ g, y0: g.position.y, amp, speed, phase }` onto
  `parts.drift` (created on first use) and returns `g`. Any future shape may use it.
- `species.js` `animateModel` gets one loop (next to `wobble`):
  ```js
  for (const d of p.drift || []) { // T35: parts that float apart and bob on their own (Dream look)
    d.g.position.y = d.y0 + d.amp * (0.5 + 0.5 * Math.sin(t * d.speed + d.phase)); // only ever up: never under the ground
    d.g.rotation.z = Math.sin(t * d.speed * 0.7 + d.phase) * 0.06;
  }
  ```
  Closed form in `t` (battle, Book portrait and world all fine). A drifting part is never `root`, `bounce`, a `legs`
  or `arms` entry (those keep their own animation); drift only touches `position.y` and `rotation.z`.
- Prototype differences to fix while porting: the prototype bobs below rest (`sin * amp`); the game version only goes
  up (the `seventh` spec checks `min.y >= -0.1`). Prototype colours become `m.body/accent/dark/belly` where it makes
  sense so evolutions can recolour.

### 2.4 Gravity and bounce blocks (`player.js`, `world.js`, `blocks.js`)

- **Gravity is the place's:** `World` gets `get gravity() { return this.realm?.gravity ?? 1; }` (T35 line). `Player.update`
  reads `const g = this.world.gravity ?? 1` once and uses it in the two gravity lines
  (`this.vel.y - 28 * g * dt` on land, `9 * g * dt` swimming). Jump speed stays 8.6, so in the Dream a jump goes
  ~2.6 blocks high instead of ~1.3 and hangs twice as long: moon jumps everywhere. With g = 1 the numbers are the
  same floats as today (main world unchanged; the `water`/`riding`/`touch` specs prove it). Sky riding ignores gravity
  as before. No upside-down gravity.
- **Bounce block** `B.BOUNCE = 87` "Bounce Block": glowing top (big up-arrow on a pink/cyan spring pattern), sides
  striped; `glow: true, noLight: true` (shows at night, lights nothing), `bounce: 14` (apex of the feet above the
  pad, in blocks), `fixed: true`, `wallText: "It's too springy to break! Jump on it instead."`. Not placeable, never in
  the main world.
- **The one check in `Player`** (land branch, right after the normal jump):
  ```js
  const under = this.onGround ? BLOCKS[this.world.get(Math.floor(this.pos.x), Math.floor(this.pos.y - 0.05), Math.floor(this.pos.z))] : null;
  this.onBounce = !!under?.bounce;                                   // T35: for the hint toast
  if (under?.bounce && k.Space) { this.vel.y = Math.sqrt(2 * 28 * g * under.bounce); this.bounced = true; } // boing!
  ```
  **Jump to launch** (not on landing): walking over a pad or dropping back down the house's entrance never traps you
  in a bounce loop, and the touch jump button works the same. Air control already exists (keys set `vel.x/z` in the
  air), so you steer to the next island while you fly. Launch speed at g 0.5 is ~19.8 blocks/s; with the 0.05 s
  frame cap that is < 1 block per step (no tunnelling).
- main.js after `p.update`: `if (p.bounced) { p.bounced = false; sound.play('boing'); }`. `sound.js`: `boing` = a quick
  springy pitch sweep (200 -> 700 Hz with a little vibrato).
- **`fixed`** (generic block flag): `editAllowed(x, y, z, id)` starts with
  `if (BLOCKS[this.get(x, y, z)]?.fixed) return false;` (T35 line in world.js). So bounce pads can't be broken by
  anyone, and `applyEdits` drops saved edits on them. Kids can never cut the route to the gym.
- **Hints** (in `realms.update`, once per session each): first time standing on a pad: "A bounce block! Jump on it to
  fly up high. Boing!"; after the first launch: "Steer while you fly to land on the next island!"; first time landing
  on the cloud sea (`p.pos.y < 3 && p.onGround`): "You fell into the cloud sea! Find a bounce block to jump back up."
