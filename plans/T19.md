## 0. Facts the design relies on (checked in the code)

- **Every gym today has ONE trainer** (`def.trainer`, `def.trainerTeam`, beaten key `<id>:trainer`, one `trainerPos`).
  The roadmap says "2 trainers + a leader, like every other gym", but only the three new gyms (and T23's) get two.
  So step 0 adds general **multi-trainer support** (§2) that leaves the 22 old gyms exactly as they are (Q1).
- `placeSlotGyms()` (gymplace.js) already loops `GYMS`, calls a builder for defs with `slot`, sets `g.slot`, pushes,
  and `generate()` runs it with `world.guardOld = true` (any write into the old 224 area throws). Slot boxes are ±24
  (49×49, all y), door direction rule for the new land: towards `MID_X/MID_Z` like `placeGym`.
- `World.set(..., false)` writes without an edit **and without marking chunks dirty**; the save only stores
  `world.edits`; a guest regenerates from seed + edits. So blocks that change at runtime (doors, lasers) need a new
  "live" setter (§3.2) that redraws but never records.
- `editAllowed` refuses every break/place inside a `protect` box (player, touch, visitors' `block` messages,
  `applyEdits`). Doors and lasers sit inside protect boxes, so nobody can break or build over them, and no save or
  visitor can ever contain an edit there.
- `game.time` (0 = 06:00 on the HUD clock, 8-minute day) is sent by the host to guests (`multiplayer.js:236`), so
  anything computed from `game.time` agrees between players. Other players' positions are in `game.mp.others`
  (`a.pos`), already broadcast; the co-op switch needs **no new message**.
- The guide golden fixture (`tests/fixtures/guide-golden.json`, `access.mjs` part A) is future-proof for new gyms
  **as long as no new access piece has `tips`**: the replay leaves later gyms unbeaten, and "nearest unbeaten gym with
  tips" would pick a new gym over the sky gyms. So: **none of the T19 pieces define `tips`.** Everything else in the
  replay only visits the old area and the first 22 ids; skip cases badge every other id (the new ones included).
- `old-saves` `SUM`/`SUM22`/`SURF` and the `big-map` old-area identity hash only the old 224 area: unchanged.
- No auto step-up in `player.js`: stairs need a jump per block (the cave stairways use 1 step per 2 blocks).

## 3. Shared building blocks (step 0)

### 3.1 Slot builders (gymplace.js)
`placeSlotGyms` keeps its loop but takes builders from a registry, so each gym's code lives in its own file:
```js
import { buildClockTower } from './clocktower.js';
import { buildHiddenHill } from './hiddenhill.js';
import { buildFirewallMaze } from './firewall.js';
const SLOT_BUILDERS = { clockTower: buildClockTower, hiddenHill: buildHiddenHill, firewallMaze: buildFirewallMaze };
...
const b = SLOT_BUILDERS[def.build];
const g = b ? b(this, def, s) : this.placeGym(def, s.x, s.z);
```
Each builder: `(world, def, slot) => gymObject`, writes **only inside `slot.box`** (guard it with a local `put(x, y, z,
id)` that throws outside the box; `guardOld` already catches the old area), and returns:
`{ def, x, z, y, front, leaderPos, trainerPos, trainerPositions, protect: [...], area: {x0,x1,y0,y1,z0,z1}, ...own }`.
Step 0 writes the three files as **stubs** that return `world.placeGym(def, slot.x, slot.z)` plus a second trainer
position and an `area`, so the three gyms exist, are protected and can be battled before B/C finish. Import cycle
(world → gymplace → clocktower → world constants) is fine: constants are only read inside functions, as gymplace does.

Step 0 also adds one shared terrain helper on `World` (gymplace.js), generalised from `buildGym`'s code (do **not**
change `buildGym`):
```js
// Levels the ground to `fy` under a rectangle (+pad) and slopes the land around it, never outside `box`;
// clears plants within rect + 5 (inside box). rect/box in world x/z, inclusive.
levelSite(rect, fy, box, pad = 2)
```
Slope = Chebyshev distance from rect+pad (like `buildGym`'s `slope`); cells outside `box` are skipped; fill uses
`groundOf(biome)`; foundation: solid STONE under rect from y 1 to fy-1 where not solid.

### 3.2 Live blocks (world.js)
```js
// Changes a block for this player only (T19 doors and lasers): redrawn, but never an edit, never saved or sent.
setLive(x, y, z, id) {
  if (!this.inBounds(x, y, z)) return;
  const i = this.index(x, y, z), old = this.data[i];
  if (old === id) return;
  this.data[i] = id;
  if (this.topReady) this.updateTop(x, y, z, id);
  this.markDirty(x, z, old, id);
}
```
`markDirty(x, z, old, id)` = the dirty-marking lines of `set` moved into a method (pure move; `set` calls it).
Also `markLitBox(x0, x1, z0, z1)` (like `markLit` for a rectangle) for the long maze building.

### 3.3 Live gym parts (`src/gymlive.js`, new)
```js
// Live gym parts: things in a gym that change while you play (the Clock Tower's doors and hand, the Firewall Maze's
// lasers). One object per gym whose def has `live`, made with every new world. They change blocks only with
// world.setLive (this player only).
import { ClockLive } from './clocktower.js';
import { MazeLive } from './firewall.js';
export const LIVE = { clock: ClockLive, maze: MazeLive };
export function createGymLive(game) { ... returns:
  reset(world)          // dispose the old ones; new LIVE[def.live](game, g) for each gym with def.live
  update(dt)            // every frame while playing
  stand(x, y, z, id)    // the block under the player's feet, every frame while on the ground
  hit(block)            // a clicked/tapped block; true = handled (reset buttons)
  prompt(block)         // text for the crosshair prompt, or null ("Reset button · click or E to reset the room")
  of(id)                // the live object of gym `id` (tests)
}
// A cell that should change, waiting while a player stands in it: a door or laser never closes on you.
export class LiveCells {
  constructor(world, player)   // player = () => game.player (it changes per world)
  want(x, y, z, id)            // remember the wanted block; applied now unless it is solid and overlaps the player
  flush()                      // call in update(): retry the waiting ones
}
```
Interface of a live object: `constructor(game, gym)`, `update(dt)`, optional `stand`, `hit`, `prompt`, `dispose`.

main.js wiring (step 0, the only main.js places):
- `game.gymLive = createGymLive(game)`; `createWorld`: `game.gymLive.reset(world)` after `populate`.
- `frame`: after `p.update(dt)`: `game.gymLive.update(dt)`; if `p.onGround`:
  `game.gymLive.stand(fx, fy, fz, world.get(fx, fy, fz))` with `fx = floor(p.pos.x)`, `fy = floor(p.pos.y - 0.05)`.
- `interact()`: before the chest line `if (target.block && game.gymLive.hit(target.block)) return true;`;
  `tapAt`: same before the chest line (within `REACH`). `updateTarget`: prompt/touch action from `gymLive.prompt`.
- `breakBlock`: protected branch uses `wallToast(BLOCKS[hit.id].wallText || 'Gym walls are too strong to break!')`
  (data on the block, §3.4).

### 3.5 Time-of-day windows (`src/daytime.js`, new, tiny)
```js
// The three door windows of the Clock Tower, by game time (0 = 06:00 on the HUD clock).
export const WINDOWS = {
  morning:   { from: 0,    to: 0.25, when: 'in the morning',   color: 'yellow',    wool: 'light' },  // 06:00-12:00
  afternoon: { from: 0.25, to: 0.5,  when: 'in the afternoon', color: 'orange',    wool: 'fire' },   // 12:00-18:00
  night:     { from: 0.5,  to: 1,    when: 'at night',         color: 'dark blue', wool: 'cosmic' }, // 18:00-06:00
};
export const windowAt = t => (t % 1 < 0.25 ? 'morning' : t % 1 < 0.5 ? 'afternoon' : 'night');
export function minutesUntil(name, t, dayLength) { const d = (WINDOWS[name].from - (t % 1) + 1) % 1; return Math.max(1, Math.ceil(d * dayLength / 60)); }
```
The three windows cover the whole day, so one door is always open (2 + 2 + 4 real minutes). A player who starts in
the morning climbs the tower in one in-game day, as the roadmap asks.

## 4. The three buildings (gym-specific files)

Local coordinates for all three: `front` = door direction (towards the start, as `placeGym`, except the hill §4.2),
`d` = steps along `front`, `s` = steps across (`side = [front[1], front[0]]`, like `buildTower`); world cell =
`x0 + front[0]*d + side[0]*s`, `z0 + front[1]*d + side[1]*s`. Every block stays inside `slot.box`.

### 4.1 Clock Tower (`src/clocktower.js`: `buildClockTower`, `ClockLive`) — slot 0
**Shape** (all numbers from the centre; `fy = clamp(terrainHeight(x0, z0), WATER_LEVEL + 1, 20)`, so the top ≤ 47):
- `levelSite` rect ±9, pad 2 (slope reaches ±20 < 24). Foundation STONE_BRICKS ring at fy around.
- **Core**: walls at Chebyshev 5 (STONE_BRICKS, corners time wool), floors (PLANKS) at `fy`, `fy+6`, `fy+12`,
  `fy+18`, roof slab of time wool at `fy+24`, stepped time-wool cap `fy+25` (±3), `fy+26` (±1), a LAMP at `fy+27`.
  Rooms: interior ±4, air 5 high per floor. 2 LAMPs on each floor (ceiling corners). GLASS windows (2 high) in the
  middle of each wall on floors 1–3, not where a door is.
- **Lobby** (ground floor): door 3 wide × 3 tall in the front wall (d = 5, s −1..1); inside a "legend" on the back
  wall: one yellow (light wool) block, two orange (fire wool) blocks stacked, three dark blue (cosmic wool) stacked =
  floors 1, 2, 3 and their colours; time-wool carpet.
- **Stairs outside**, 2 wide, on the ring at Chebyshev 6–7 along the **left, back and right** sides (never the front,
  where the clock is). Walk order index `i` (both cells of the band share it): left side (s ≤ −6, d > −6):
  `i = 7 − d` (d 7..−5 → i 0..12); back (d ≤ −6): `i = 13 + (s + 7)` (s −7..7 → 13..27); right (s ≥ 6, d > −6):
  `i = 28 + (d + 5)`, stopping at `i = 37`. Step block height `h(i) = fy + 1 + floor(i / 2)` (one step up every 2
  blocks, like the cave stairways), column filled solid (STONE_BRICKS) from the ground up to `h(i)`. Landings fall
  out of the formula: `h = fy + 6k` at `i = 12k − 2, 12k − 1` → floor 1 at the left side d = −3/−4, floor 2 at the
  back s = 2/3, floor 3 at the right side d = 1/2 (i 34..37 flat at fy+18). **Railing**: GLASS 2 high
  (`h(i)+1..h(i)+2`) on Chebyshev 8 next to every stair cell.
- **Floor doors** in the core wall beside each landing: 2 wide (the landing's two cells) × 3 tall
  (`fy+6k+1..+3`), generated **closed** (`CLOCK_DOOR`). A frame round each door in its window's wool (floor 1 yellow
  `WOOL.light`, floor 2 orange `WOOL.fire`, floor 3 dark blue `WOOL.cosmic`): the wall cells right of/left of and
  above the door.
- **People**: trainer 1 in floor 1's room (`fy+7`), trainer 2 floor 2 (`fy+13`), leader floor 3 (`fy+19`), each 2
  cells in from their door. `leaderPos`, `trainerPos`, `trainerPositions`.
- **Clock face** (blocks) on the front, one block in front of the wall (d = 6), centre `(s 0, y fy+14)`: cells with
  `s² + (y − cy)² ≤ 5.5²`; rim (> 4.2) coloured by angle, inner PAPER wool, centre block time wool. Angle as seen by
  someone in front looking at it, clockwise from the top: `α = atan2(sRight, y − cy)` with `sRight` = the cell's
  offset along the viewer's right (`right = [front[1], -front[0]]`). Rim colour: α in [−π/2, 0) yellow (morning),
  [0, π/2) orange (afternoon), else dark blue (night); 4 LAMPs at the quarter marks (06, 12, 18, 24) on the rim.
  So the dial is a **24-hour dial**: 06:00 on the left, noon at the top, 18:00 on the right, midnight at the bottom;
  the day half is light, the night half dark. Kids read it as "when the hand reaches a colour, that door opens".
- Gym object extras: `floors: [{ window, door: [[x,y,z], ...6 cells], room: box }]` (index = trainer order, last =
  leader), `face: { centre: [x, y, z], front, right }`.

### 4.2 Hidden Hill (`src/hiddenhill.js`: `buildHiddenHill`; disguises in `npc.js`) — slot 1
**Shape** (`fy = clamp(terrainHeight(x0, z0), WATER_LEVEL + 2, 26)`; hill radius `HR = 18`, top `fy + 12`):

  its own biome's blocks, the hill is made of exactly what is around it (grass/dirt, sand, snow...).

**`MazeLive`** (runtime):

- `stand(x, y, z, id)`: `SWITCH_RED` → phase 1, `SWITCH_BLUE` → phase 0 for the room that owns the switch; on a

- apply: red cells → `phase ? AIR : LASER_RED`, blue cells → `phase ? LASER_BLUE : AIR`, friend cells →
  `friend ? AIR : LASER_FRIEND`, all through `LiveCells.want` (a laser never turns on inside you; it waits until you
  step out).
- **State is per player** (Q2): each player has their own lasers and switches; your friend's avatar may look like
  it walks through your lasers. The friend pad is the one shared thing (from positions already sent). Nothing
  saved: after a reload every room is back at the start.
- Single player: friend lanes never open (never needed).
