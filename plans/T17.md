# T17 · Bigger map and protected gyms (plan)

Owner (ROADMAP, waves 7–8): the map grows to **288×288** (64 new blocks east (+x) and south (+z)); the old
224×224 area stays **block for block** the same; new gyms (T19 now, T23 later) go **only in the new land**, in
**5 reserved spots**; the start point stays; the seam at 224 looks natural; **gyms can't be broken into or built
in**; `WORLD_VERSION` bump; load time and memory measured on the slow renderer with an iPad-sized viewport.

Read first: `CLAUDE.md` (determinism rules, old saves, gyms 17+, T8/T10 notes, test gotchas), `plans/T8.md` §3–4
and `plans/T10.md` §2 (cave/sky gyms, `newGymBoxes`, the `old-saves` checksums). T16 (guide → `access.js`) and
T18 (Time/Camo/Cyber species) are built **at the same time**: see §9 for files to keep out of.

## 0. Measured (prototype on a copy of `src/`, nothing in the repo changed)

- **Terrain has no edge falloff.** `terrainHeight(x, z)` (world.js:189) is pure fbm noise at absolute x/z; the
  map edge just cuts it. What "happens at today's edge" is only: the invisible wall (`isSolid` out of bounds,
  world.js:119), no plants in the last 3 columns (plant loop `3 .. W-3`, world.js:276), no caves within 4 of the
  edge (`keepOutMask`, caves.js:24) and faces drawn on the outside of the last column. All of that is written in
  terms of the map size, so it moves to the new edge by itself.
- **Nothing old reaches the seam.** The latest the old generation writes is x/z ≤ 222 (gyms ≤ 207 + slope 15;
  tower ≤ 205 + 15; Saucer cut ≤ 219, its plant clearing ≤ 222; trees ≤ 222; caves ≤ 219; stairways ≤ 221).
  Prototype on seeds 1–12: column 223 / row 223 is natural terrain on **every** column, and the steps across
  223|224 are 0–2 blocks, the same as anywhere else. So the seam needs **no blending**: the terrain simply goes on.
- **The "legacy sandbox" approach works** (§1.2): generating the old 224 map exactly as today in its own 224×224
  `World`, copying it into the 288 world, then generating the new land around it. Prototype results for seeds 1
  and 4242: `old-saves` `SUM`, `SUM22`, `SURF`, terrain 596409 and the 16 gym positions are **all identical**
  (loops restricted to the old area). Start columns identical: `{1: [112, 15, 112], 4242: [120, 15, 111],
  294331207: [94, 17, 96]}` (x, feet y, z).
- **Slots** (§2), 200 seeds: 5 slots found on 200/200, ~5 ms; 97 % of slots pass the `dryAt` rule (the rest are
  beach/shallow water: `buildGym` already builds a stone foundation there); slot distances from the start 136–195;
  the farthest slot (Treasure) has ground ≥ 18 within its box on 198/200 seeds (room for T23's tunnel).
- **Cost** (`perf.mjs` in §7, iPad viewport 820×1180 @2x, SwiftShader, 3 interleaved runs, medians; the machine
  is noisy, so ±25 %):

  | | 224 today | 288 prototype | change |
  | --- | --- | --- | --- |
  | page start → title world ready | 2.3 s | 2.9 s | +0.6 s (+25 %) |
  | `generate()` | 740 ms | 940 ms | +27 % |
  | `buildAll()` (meshing) | 670 ms | 750 ms | +12–40 % |
  | JS heap after GC | 61 MB | 83 MB | +22 MB |
  | chunk geometry (GPU estimate) | 35 MB | 55 MB | +20 MB |
  | draw calls, at the start looking east | 200–240 | 310–380 | +50 % |

  **Not much slower**; the draw calls are the one thing worth trimming (§6, distance culling). Freeing the CPU
  copies of chunk geometry after upload saved another ~20 MB in a test but **is not recommended**: three.js needs
  the arrays to re-upload after a WebGL context loss (iPad Safari does that when backgrounded).

## 1. The map grows (world.js, caves.js, gymplace.js)

### 1.1 Constants (world.js:8–10)
```js
export const WORLD_W = 288;            // the map since T17 (array stride of every World made by the game)
export const WORLD_D = 288;
export const OLD_W = 224, OLD_D = 224; // the map before T17: generated exactly as before, never changes
export const MID_X = 112, MID_Z = 112; // the old middle: the start search, gym doors and the title fly-over use it
const NO_SIZE = [192, 192];            // (was OLD_SIZE) saves from before sizes were recorded
```
`WORLD_W`/`WORLD_D` keep meaning "the size of the game's world", so every runtime user (creatures, guide,
multiplayer, saves) needs no change.

### 1.2 One idea: the old map is generated in its own 224 World, then copied in
- `constructor(seed, scene, materials, [W, D] = [WORLD_W, WORLD_D])` stores `this.W`, `this.D` and sizes
  `data`/`ground`/`top`/`litCol` from them.
- Every **method** of `World` (world.js), `GymPlacement` (gymplace.js) and the carvers (caves.js) uses the
  instance's `this.W`/`this.D` (`world.W`/`world.D`) instead of the module constants, except the few pinned ones
  in the table below. On a 224 instance this is exactly today's code.
- Rename today's `generate(opts)` body to **`generateArea(opts)`, unchanged** (except the two helper
  extractions below). New `generate`:
  ```js
  generate(opts = {}) {
    if (this.W === OLD_W && this.D === OLD_D) return this.generateArea(opts); // the old map (also used by tests)
    const old = new World(this.seed, null, null, [OLD_W, OLD_D]);
    old.generateArea(opts);
    this.adoptOld(old);           // §1.3
    this.generateNewLand();       // §1.4: writes only outside the old area
    if (opts.slotGyms !== false) this.placeSlotGyms(); // §2.3 (no slot gyms until T19)
    this.gyms.sort((a, b) => GYMS.indexOf(a.def) - GYMS.indexOf(b.def));
  }
  ```
- Extract (pure moves, same statements): `fillColumn(x, z)` = the body of the terrain loop (world.js:240–257,
  sets `ground`, writes the column, returns the biome) and `plantAt(x, z, biome, wide = true)` = the body of the
  plant loop (world.js:278–296; with `wide === false` it skips `placeTree`/`placePine`, keeps cacti, crystals and
  flower bushes). `generateArea` calls them in the same loops as today.

### 1.3 `adoptOld(old)` (world.js, new)
Row copies (`TypedArray.set` with `subarray`): `data` per (y, z) row of 224 into `this.index(0, y, z)`; `ground`
and `litCol` per z row. Remap the column-index sets of the caves (`c = x + z*224` → `x + z*288`):
`old.caves.opened`, `old.caves.marks`. Then take over by reference: `caves`, `gyms`, `tower`, `litRooms`,
`newGymBoxes`, `high`, and the spot caches `extraSpots`, `caveSpots`, `newSpots` (coordinates are absolute, so
nothing else needs remapping; gym objects already carry their `protect` boxes from §4). `old` is garbage after.

### 1.4 `generateNewLand()` (world.js, new)
`inOld(x, z) = x < OLD_W && z < OLD_D`.
1. Terrain: for every column with `!inOld(x, z)`: `biomes[c] = this.fillColumn(x, z)` (same noise, same ores, same
   biome rules; `biome()` uses the pinned `highGround()`, so thresholds come from the old area as before).
2. Plants: for `x` in `3 .. W-4`, `z` in `3 .. D-4`, `!inOld(x, z)`:
   `this.plantAt(x, z, biomes[c], !(x < OLD_W + 2 && z < OLD_D + 2))`. Trees/pines have crowns of radius 2, so
   their trunks start 2 columns past the seam (x ≥ 226 or z ≥ 226) and never touch the old area; single-block
   plants start at 224. (The old side has no plants at 221–223 already, so a ~5-column strip along the seam has
   fewer trees. Acceptable; the prototype looked natural.)
3. **No caves in the new land** (decision §10.4). Nothing else.
4. Safety: during `generateNewLand` and `placeSlotGyms`, a debug guard is cheap: in `set()`, when
   `this.guardOld` is true and `inOld(x, z)`, throw. Set it around these two calls only.

## 2. Five reserved gym slots in the new land (gymplace.js)

### 2.1 `newLandSlots()` (cached in `this.slots`; terrain only: depends on the seed and constants, nothing else)
```js
// The 5 places in the new land where gyms 23+ go (T19: slots 0-2, T23: 3-4). Terrain only. NEVER change the
// rules: it would move these gyms in every world made since T17.
export const SLOT_R = 24, SLOT_GAP = 56;
newLandSlots() {
  if (this.slots) return this.slots;
  const h = (x, z) => Math.min(this.terrainHeight(x, z), WORLD_H - 10);
  const dry = (x, z) => [[0, 0], [6, 6], [-6, 6], [6, -6], [-6, -6]].every(([a, b]) => h(x + a, z + b) > WATER_LEVEL);
  const score = (x, z) => {
    let n = 0;
    for (let a = -16; a <= 16; a += 8) for (let b = -16; b <= 16; b += 8) { const g = h(x + a, z + b); if (g > WATER_LEVEL && g <= 26) n++; }
    return n + (dry(x, z) ? 5 : 0);
  };
  const cands = []; // centres whose ±24 box lies inside the new land and the map
  for (let z = 28; z <= 260; z += 4) for (let x = OLD_W + SLOT_R; x <= 260; x += 4) cands.push([x, z]); // east strip and corner
  for (let x = 28; x <= OLD_W + 20; x += 4) for (let z = OLD_D + SLOT_R; z <= 260; z += 4) cands.push([x, z]); // south strip
  const scored = cands.map(([x, z], i) => ({ x, z, i, s: score(x, z) })).sort((a, b) => b.s - a.s || a.i - b.i);
  const picked = [];
  for (const c of scored) {
    if (picked.length === 5) break;
    if (picked.every(p => Math.max(Math.abs(p.x - c.x), Math.abs(p.z - c.z)) >= SLOT_GAP)) picked.push(c);
  }
  const d = c => Math.hypot(c.x - MID_X, c.z - MID_Z);
  picked.sort((a, b) => d(a) - d(b) || a.i - b.i); // slot 0 = nearest the start
  return (this.slots = picked.map(({ x, z }, k) => ({ k, x, z,
    box: { x0: x - SLOT_R, x1: x + SLOT_R, z0: z - SLOT_R, z1: z + SLOT_R, y0: 0, y1: WORLD_H - 1 } })));
}
```
Expected (prototype, same code): seed 1 `[[136,248],[80,248],[260,132],[260,48],[192,252]]`, seed 4242
`[[84,248],[140,248],[28,248],[248,204],[252,260]]`, seed 777 `[[248,92],[144,248],[252,152],[248,28],[248,248]]`.
The builder re-checks these with the real code and puts them in the spec as a fixture (they must never change).

Why this shape: boxes (49×49) never overlap the old area (x0 ≥ 224 or z0 ≥ 224), stay ≥ 3 from the outer edge,
are ≥ 7 apart from each other; `buildGym`'s slope (±15) and tree clearing (±11) fit well inside. Slot boxes are
far from old gyms (old buildings end ≤ 214, slopes ≤ 222).

### 2.3 `placeSlotGyms()` (gymplace.js, new; T19 fills it in)
```js
placeSlotGyms() {
  const slots = this.newLandSlots();
  for (const def of GYMS) {
    if (def.slot == null) continue;
    const s = slots[def.slot];
    const g = def.build ? this[def.build](def, s) : this.placeGym(def, s.x, s.z); // T19: def.build = 'buildClockTower' etc.
    g.slot = s;
    this.gyms.push(g);
  }
}
```
No `GYMS` entry has `slot` yet, so T17 places nothing. T19 reads `world.newLandSlots()[def.slot]` and adds its
builders (each returning a gym object with `protect` boxes, §4).

## 4. Protected gyms (one rule for all 22 gyms, the tower and every later gym)

### 4.1 Boxes come from placement (gymplace.js)
Each gym object (and `world.tower`) gets **`protect: [{ x0, x1, y0, y1, z0, z1 }]`** (inclusive), set where the
object is made, so T19/T23 builders do the same:
| Kind | Made in | Box |
| --- | --- | --- |
| Surface gym (incl. Fossil fallback, T10 Sunbeam/Origami/Goo fallback) | `placeGym` non-cave branch | `x ± 7, z ± 7, y 1 .. H-1` (walls ±6, door pillars/lanterns/fossil arch at 7) |
| Cave gym (Fossil, Goo) | `placeGym` cave branch | `x ± 13, z ± 13, y 1 .. fy + 13` (the cavern, RC 13, air ≤ 14, plus one roof layer). The stairway outside 13 stays open. |
| Sky gym (Cloud, Saucer) | `placeSkyGym` | `x ± 10, z ± 10, y fy - 3 .. H-1` (island r² ≤ 110 ⇒ |a| ≤ 10; underside to fy − 3). The **pad at d = 11–12 and the pillar column on it are outside**, so the climb works; so do the lamp post and the ground under the island. |
| Tower | `placeTower` | `x ± 7, z ± 7, y 1 .. H-1` |
Full-height columns stop both digging in from below and building over the roof. Natural blocks under surface
gyms (foundation) are inside, so no tunnelling in.

### 4.2 World API (world.js)
```js
// The gym (or tower) whose protected box holds this cell, or null.
protectedAt(x, y, z) { ... over this.gyms and this.tower, their protect boxes ... }
// May this cell become `id`? One rule for the player, touch, visitors and saved edits.
// Opening a chest is not breaking (cave chests, T23's key chests on the vault roof).
editAllowed(x, y, z, id) { return !this.protectedAt(x, y, z) || (this.get(x, y, z) === B.CHEST && id === B.CHEST_OPEN); }
```
`applyEdits(edits)` skips edits whose cell is not `editAllowed` (decode `i`: `x = i % W`, `z = ⌊i / W⌋ % D`,
`y = ⌊i / (W·D)⌋`), so old saves with holes dug into gyms get their gym back (decision §10.1) and a host's world
sent to a guest is cleaned the same way.

### 4.3 Where it is enforced (main.js, multiplayer.js)
- `breakBlock(hit = target.block)` (main.js:482): after the chest line, `if (!world.editAllowed(hit.x, hit.y,
  hit.z, B.AIR)) { wallToast(); return; }`.
- `placeBlock(hit = target.block)` (main.js:517): after computing x, y, z, `if (!world.editAllowed(x, y, z,
  id)) { wallToast(); return; }`.
- `wallToast()`: `"Gym walls are too strong to break!"` (break) / `"You can't build inside a gym!"` (place,
  decision §10.3), at most once every 2 s (`performance.now()` stamp), no sound (sound.js is T18's).
- The optional `hit` parameter lets tests pass a cell directly (`game.breakBlock({ x, y, z, id, normal })`).
- Touch: `touch.js` calls the same `breakBlock`/`placeBlock` through the actions; nothing to change there.
- Visitors: multiplayer.js:239–242 `t.on('block')`: `if (!this.game.world.editAllowed(p.x, p.y, p.z, p.b))
  return;` before `set`.

## 6. Load time, memory, draw calls
1. **Before any change**: run `perf.mjs` (§7) 3× on the unchanged checkout; note medians in the PR/plan.
2. **Distance culling** (world.js + one line in main.js): `World.cull(pos, far)` sets `mesh.visible` for each
   chunk's meshes to `(cx·16 + 8 − pos.x)² + (cz·16 + 8 − pos.z)² < (far + 12)²`; call
   `game.world.cull(camera.position, scene.fog.far)` just before `renderer.render` (main.js:878). Everything past
   the fog's far end is fog-coloured already (all chunk materials are `MeshBasicMaterial`, fog on), so nothing
   visible changes; it only cuts draw calls (fog far is 100 by day, 40 in caves, less in fog weather).
3. **After**: run `perf.mjs` 3× again. Report in this plan (append a "Result" table) and in the PR. If the page
   start → world ready time grows by more than ~1 s or the heap by more than ~40 MB on the slow renderer, say so
   to the owner before merging.

   blocks inside a gym).

   to break!"). Alternative: the same break text for both.

   way caves came to old worlds (below a 3-block roof), with the new land's slot boxes kept out. T23 carves its
   own tunnel for the Treasure Gym.

   flag `toldBigMap`). **Off by default**: T19's "new gyms have appeared" toast already points there.
