# T40b · 🏴‍☠️ Pirate type and the Pirate Seas

Read first: `CLAUDE.md`, `plans/T40.md` (wave 14 shared decisions **and its "## Base" section: this plan uses its APIs**),
`ROADMAP.md` "Wave 14", `STORY.md` "The Pirate Seas". Models: `plans/T37.md` (a type), `plans/T35.md` + `src/dreamland.js`
(realm terrain as data, Node-runnable), `src/swirlland.js` (lift boxes, keeps), `src/treasurevault.js` (`VaultLive`: state
drawn from saved data with `setLive`), `src/portal.js` (meshes made per world, removed on the next one).

**What it is.** Open ocean and scattered islands, ruled by **Captain Squawk**, a parrot pirate who took over this world
when the Wizard was gone. You **fly by cannon** from island to island, **swing on ropes** over the water, **board his
ship**, beat him, and his **treasure chest** pops open: the star was inside. Falling in the sea is never a fail: you swim
(or ride a water creature) to a beach or a rope ladder. Nothing to solve, only things to do. iPad first: the big action
button says `Fire!` or `Swing!`; no new buttons, no questions (`ui.ask` is not used).

Base names used below (plans/T40.md "## Base"): `pictureRealm` (B.4), `stash.up` travel and `lose: 'stay'` + `world.rests`
(B.5), `kit` / `buildWayBack` / `placeBoss` / `placeCrew` / `pictureAim` (B.7, `src/picturelands.js`), `addBoss` / `BOSS` /
`crewKey` (B.8, `src/pictureboss.js`), `world.parts` + `LIVE` + the `action(block)` hook (B.9), `Mover` / `PATHS` +
`player.carry` (B.10, `src/mover.js`), `world.realmBiome` (B.4), `levelCap` (B.13). Where this plan needs one more small
generic piece, it is listed in **"Asks of the base"** at the end (only two).

### 2.2 Shapes (section `/* ==== T40b pirate ==== */` at the end of `shapes.js`)

  three-cornered hat with gold trim, over the bandana), `coat` (red coat tails over the tail base), `hook` (a gold hook at
  one wing tip).
- **`hookcrab`**: a wide flat shell (0.8 x 0.3 x 0.55), six legs (three a side, two-part pivots that step), two eye stalks,
  one **pincer** (two halves that open and close) and one arm ending in a **gold hook** (three small boxes in a J). Bandana
  knotted on the shell between the stalks. The body sways sideways (a sidestep look). Extras: `anchor` (the hook arm
  becomes an iron anchor: shank, stock, two flukes, a gold ring on the shank keeps `gear: 'gold'`), `barnacles` (pale bumps).
- **`shipbottle`**: a **glass bottle lying on its side** along z (box 0.5 x 0.5 x 0.9 with its own `MeshLambertMaterial`,
  `transparent: true, opacity: 0.35, depthWrite: false`, `renderOrder` 2), a neck at the front, a tan cork, two eyes on the
  glass shoulder; inside a **tiny ship**: brown hull, a mast, a white sail with a red stripe and a little striped flag on
  top (`gear: 'bandana'`); a gold band round the neck (`gear: 'gold'`). It rocks (swing z 0.12) and bobs. Extra `masts3`:
  three masts and sails. Only the glass is transparent (check a battle hit flash on it in the screenshot).
- **`barrelpus`**: a **wooden barrel** body (staves in `accent`, dark hoops) with an **octopus head** poking out of the top

  spyglass** to one eye (three gold segments, `gear: 'gold'`) that sweeps slowly left and right (swing y). Bandana on the head.

`roster` wants 3+ shapes per type: there are 4.

### 3.3 The cannon (a `Mover` on an `arc` path)

`cannonSpec(c)` (pure, pirateland.js) gives the base's arc spec, so PirateLive and the spec agree:

```js
// S = the pad's stand point (pad centre, feet = pad top + 1); E = the target centre (feet = target top + 1).
export function cannonSpec(c) {
  const dist = Math.hypot(E[0] - S[0], E[2] - S[2]);
  const time = Math.min(4, Math.max(1.4, 0.8 + dist / 22));           // seconds in the air
  const height = Math.min(44 - Math.max(S[1], E[1]), Math.min(16, Math.max(6, dist * 0.3))); // top of the arc above the higher end
  return { kind: 'arc', from: S, to: E, height, time };                // makePath(spec) = the base's closed form
}
```

How it plays (PirateLive):
1. Standing within 1.5 of a pad centre, on the ground: prompt `Cannon to Parrot Perch · ${how} to fire!`, action `Fire!`.
2. Pressing it (E, the action button, a tap or click on the pad / carriage): `game.riding.stop('quiet')`, face the target
   (set `p.yaw` once; looking around stays free), `cannonboom`, a smoke puff at the muzzle, the barrel kicks back (mesh,
   0.2 s), then `new Mover({ path: makePath(cannonSpec(c)), run: 'ride', canLeave: false, onEnd })` and `board(p)`. No
   loading animation (the boom is the start: quicker for a child).
3. `onEnd`: the Mover puts you at the end (feet on the target), a sand puff, `place`; control is back.
4. The base's `player.carry` hook moves you (no collision while carried): the spec proves every arc clear of the terrain,
   and the ends are keeps (nobody can build on a target). A block a player builds mid-air on the way is simply passed.
5. Clock: PirateLive calls `mover.update(dt)` only while the game is playing and not in a battle (Ask 2), so a pause
   or a battle freezes the flight.
6. Other players on the target do not matter (avatars are not solid).

### 3.4 The rope swing (`PATHS.swing`, closed form)

The only Pirate-only path. `swingPath(r, from)` (pure, pirateland.js), registered in pirateparts.js as
`PATHS.swing = ({ rope, from }) => swingPath(rope, from)`:

```js
// a, b = the stand points (equal feet y); M = their middle; s = half the distance; (ux, uz) = unit a -> b.
export function swingPath(r, from = 'a') {
  const h = Math.max(5, Math.ceil((s * s - 9) / 6));          // anchor height above the feet: the lowest feet stay >= feet - 3
  const L = Math.hypot(s, h), th0 = Math.atan2(s, h), k = from === 'a' ? 1 : -1;
  const time = Math.min(2.4, Math.max(1.2, Math.PI * Math.sqrt(L / 28))); // half a pendulum swing at our gravity (28)
  const yaw = Math.atan2(-ux * k, -uz * k);
  return { time, loop: false, anchor: [M.x, feet + h, M.z], L,
    at(t) {
      const u = Math.min(1, Math.max(0, t / time)), th = th0 * Math.cos(Math.PI * u), off = -L * Math.sin(th) * k;
      return { x: M.x + ux * off, y: feet + h - L * Math.cos(th), z: M.z + uz * off, yaw }; // off: -s (start) -> +s (end)
    } };
}
```

Rules: span `2s <= 16`, both stands on tops of the same height, anchor at most y 30, lowest feet `>= 14` (the water surface
is 13). A pendulum is at rest at both ends, so the start and the landing are soft. How it plays: within 1.6 of a stand point,
on the ground: prompt `Rope to Crab Rock · ${how} to swing`, action `Swing!`. Press: riding stops, `whoosh`, a Mover on the
swing path (`canLeave: false`), at the end your feet are on the other stand, control back. Each rope works from either end.

**The rope mesh:** one thin box per rope (0.12 wide, rope brown) from the anchor to the hand (feet + 1.6) while you swing;
idle it hangs towards the end nearer the player (angle `+-0.85 th0`, eased over 0.6 s), so its end is beside the post you
stand at. All ropes are one `InstancedMesh` (1 draw call).
