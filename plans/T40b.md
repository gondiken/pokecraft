# T40b · 🏴‍☠️ Pirate type and the Pirate Seas

Read first: `CLAUDE.md`, `plans/T40.md` (wave 14 shared decisions **and its "## Base" section**), `ROADMAP.md` "Wave 14",
`STORY.md` "The Pirate Seas". Models to copy from: `plans/T37.md` (a type), `plans/T35.md` + `src/dreamland.js` (realm
terrain as data, Node-runnable), `src/swirlland.js` (lifts, keeps), `src/portal.js` (realm meshes made in `reset`, removed
on the next one), `src/treasurevault.js` (`VaultLive`: state drawn from saved data with `setLive`).

**What it is.** Open ocean and scattered islands, ruled by **Captain Squawk**, a parrot pirate who took over this world
when the Wizard was gone. You **fly by cannon** from island to island, **swing on ropes** over the water, **board his
ship**, beat him, and **open his treasure chest**: the star is inside. Falling in the sea is never a fail: you swim (or
ride a water creature) to a beach or a rope ladder. Nothing to solve, only things to do. iPad first: the big action
button says `Fire!`, `Swing!` or `Open!`; no new buttons.

Everything below that says "base" is the T40 base. Where this plan needs something from it, see **"Base assumptions"**
at the end (the base section of `plans/T40.md` was still empty when this plan was written: the orchestrator reconciles).

### 3.3 The cannon (closed form)

Pure function in pirateland.js, used by PirateParts and by the spec:

```js
// S = the pad's stand point (pad centre, feet y = pad top + 1), E = the target's centre (feet y = target top + 1).
export function cannonPath(c) {
  const dist = Math.hypot(E.x - S.x, E.z - S.z);
  const T = Math.min(4, Math.max(1.4, 0.8 + dist / 22));                          // seconds in the air
  const H = Math.min(44, Math.max(S.y, E.y) + Math.min(16, Math.max(6, dist * 0.3))); // highest feet
  const A = H - (S.y + E.y) / 2;
  const at = u => [S.x + (E.x - S.x) * u, S.y + (E.y - S.y) * u + 4 * A * u * (1 - u), S.z + (E.z - S.z) * u]; // u = t / T
  return { S, E, T, H, at, LOAD: 0.4 };
}
```

How it plays (PirateParts):
1. Standing on (or within 1.5 of) a pad, on the ground: prompt `Cannon to Parrot Perch · ${how} to fire!`, action
   `Fire!`. Pressing it (E, the action button, a tap on the pad or carriage, a click on them) starts **loading**: stop
   riding (`game.riding.stop('quiet')`), face the target (`p.yaw` once; looking around stays free), feet slide to the
   muzzle in `LOAD` 0.4 s.
2. **BOOM**: `cannonboom`, a smoke puff at the muzzle, the barrel kicks back (mesh, 0.2 s). The flight follows `at(t/T)`.
3. **Landing**: at `u = 1` the feet are exactly on the target; velocity 0, a sand puff, `place` sound; control is back.
4. **How the player is moved:** no change to `player.js`. `main.js` runs `p.update(dt)` and then the live parts; while
   carrying, PirateParts sets `p.pos` to the path point and `p.vel` to 0 **after** `p.update`, every frame (the camera
   copies `p.pos` after that). Keys do nothing; the mouse / drag still looks around.
5. **Clock:** the sum of the frame `dt` (already clamped to 0.05 by `frame()`), only while `playing()` and not in a battle
   (a pause or a battle freezes the flight; it goes on afterwards). Never `performance.now()`.
6. **Collisions on the way:** the spec proves every arc is clear of the terrain. A player-built block can still be in the
   way: before each step, `if (p.collides(next))` the flight stops where it is ("Bonk! Something was in the way."),
   velocity 0, normal physics again: you drop (mostly into the sea). Never inside a block, never stuck.
7. Other players on the target do not matter (avatars are not solid): the cannon always fires.

### 3.4 The rope swing (closed form)

```js
// a, b = the stand points (feet y equal); M = their middle; s = half the distance; h = the anchor's height above the feet.
export function ropePath(r) {
  const h = Math.max(5, Math.ceil((s * s - 9) / 6));     // so the lowest feet stay >= feet - 3 (out of the water)
  const L = Math.hypot(s, h), th0 = Math.atan2(s, h);
  const T = Math.min(2.4, Math.max(1.2, Math.PI * Math.sqrt(L / 28)));   // half a pendulum swing at our gravity
  const at = (u, from = 'a') => {                       // u = t / T; from 'b' runs the other way
    const th = th0 * Math.cos(Math.PI * u), off = -L * Math.sin(th);    // off along a -> b from M: -s at the start, +s at the end
    const k = from === 'a' ? 1 : -1;
    return [M.x + ux * off * k, A.y - L * Math.cos(th), M.z + uz * off * k];
  };
  return { A, L, T, h, at, GRAB: 0.25 };                // A = anchor (M.x, feet + h, M.z); (ux, uz) = unit a -> b
}
```

Rules: span `2s <= 16`; both stand cells on tops of the same height; the anchor at most y 30; the lowest feet
`A.y - L >= 14` (above the water surface 13). The swing starts and ends at rest (that is how a pendulum is at its ends),
so the landing is soft. How it plays: within 1.6 of a stand point, on the ground: prompt `Rope to Crab Rock · ${how} to
swing`, action `Swing!`. Press: `GRAB` 0.25 s (feet slide to the stand point), `whoosh`, the swing, at the end feet on
the other stand point, control back. Moved exactly like the cannon (pos after `p.update`, clock from summed `dt`, a bonk
drops you). Each rope can be used from either end.

**The rope mesh:** one thin box per rope (0.12 wide, rope brown), from the anchor to the hand (feet + 1.6) while you
swing; idle it hangs towards the end nearer to the player (angle `+-0.85 th0`, eased over 0.6 s when you walk to the
other end), so its end is always beside the post you are standing at. All ropes are one `InstancedMesh` (1 draw call).

  `src/realmparts.js` with exactly this interface and these 6 lines (T40a/c/d can then register their own).
- **B7. Wild levels:** `creatures.wildLevel`'s cap `40 + levelBonus` must let a realm reach ~55 (e.g. the cap becomes
  `40 + levelBonus + (realm.levelBonus ?? 0)`); T40b sets `levelBonus: 34` for wild levels ~45-55.
- **B8. Sea spawns:** `creatures.biomeAt` in a realm returns `realm.waterBiome` on water when the realm has one (one
  line; T40b adds it if the base did not).
- **B9. Stars and HUD:** `game.stars`, the star HUD row and the bridge stone are the base's (the Pirate Seas star lights
  its stone as `BRIDGE_WORLDS` says).
- **B10. Shared gadgets:** if the base ships a shared `Mover` (a scripted player path with a summed-dt clock, the bonk rule
  and hand-back) or `Launcher`, PirateParts uses it with `cannonPath` / `ropePath` as the paths instead of its own carry
  code; the behaviour in 3.3 / 3.4 stays.
