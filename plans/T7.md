# T7 · Attack animations (plan)

Goal (ROADMAP T7): every move gets a small animation, at least one per type (19 types, 87 moves), special
ones for the 7 signature moves (`sig`), small ones for move effects (heal, stat up/down, sleep, flinch,
recoil, miss, multi-hit). Keep the red hit flash. Cheap on iPad, works at 1–2 fps in tests, never blocks
or changes a battle, and **never touches `battle.rng`** (duels must stay in step).

Files: new `src/fx.js` (engine + kit + status effects), new `src/fxrecipes.js` (per-type and signature
recipes), `src/battle.js` (calls), `src/main.js` (create, update, clear, pause toggle), `index.html`
(one button), `src/sound.js` (type sounds + `has()`), `tests/specs/fx.mjs` (new), one line in
`tests/specs/moves.mjs` and `sound.mjs`, `README.md`, `CLAUDE.md`. No save-format change.
`duel.js` `VERSION` is **not** bumped (battle rules and draw order do not change).

## 1. Design rules (both builders)

- **Time-based, closed form.** Every effect has `t0` (from `performance.now()`) and `dur` (ms). Each frame
  `p = min(1, (now - t0) / dur)` and the recipe's `step(p)` puts every object where it belongs *at p*
  (no velocities integrated per frame). So 1–2 fps just shows fewer frames, the effect still ends on
  time, and tests can freeze any moment. Do **not** use the game loop's `dt` (main.js caps it at 0.05 s).
- **Randomness:** `Math.random` only, drawn once when the effect starts (per-particle seeds in a
  `Float32Array`). Never `battle.rng`, never `mulberry32` of the duel seed.
- **Never blocks the battle.** Only the travel part of an attack is awaited, ≤ 450 ms (signature ≤ 700 ms).
  Impacts and status effects are fire-and-forget and run alongside the existing `say()` pauses. Every
  effect promise also resolves from a `setTimeout(dur + 400)` fallback (hidden tab: rAF stops), unless
  `fx.hold` is set. `fx.clear()` resolves all pending promises.
- **Budget:** at most 6 live effects (oldest is finished early when a 7th starts); ≤ 300 live points in
  total; ≤ 3 `Points` + 8 meshes/sprites per effect; ≤ 12 extra draw calls in the worst moment. No lights,
  no shadows, no per-frame allocation (reuse module-level temp vectors). No full-screen flashes; electric
  bolt re-jags at most every 90 ms (no strobe for kids).
- **Look:** blocky/pixel like the game. Shared 32×32 canvas textures with `NearestFilter`. Materials are
  `transparent`, `depthWrite: false`, `fog: false` (so they glow in caves and at night); `glow: true` uses
  `AdditiveBlending` (fire, electric, pixie, cosmic, rainbow, alien sparkles); dark things (ghost shadow,
  toxic, dust) use normal blending.
- **Shared vs owned.** Textures and the 4 shared geometries (unit box, ring, disc, cone) are created once,
  lazily, and kept for the whole session. Each effect owns its `Points` `BufferGeometry` and all its
  materials and disposes them when it ends. `fx.stats = { made, disposed, live, points }` counts owned
  geometries+materials (tests check `made === disposed`).

## 2. `src/fx.js` (builder A)

```js
export class Fx {
  constructor(scene)            // this.root = new THREE.Group() (name 'fx'), added to scene once
  on                            // localStorage 'pokecraft-fx' !== 'off' (try/catch), default true
  setOn(on)                     // stores it; off -> clear()
  hold = null                   // tests: number 0..1 freezes every effect at that progress
  active = new Set()
  stats
  update(now)                   // main.js frame loop, every frame (also when paused / title)
  attack(moveId, from, to)      // travel from attacker spot to target spot; Promise (awaited by battle)
  impact(type, to, { big })     // burst on the target, one per hit; Promise (not awaited)
  status(kind, spot, opts)      // see §4; Promise (not awaited)
  aura(type, spot)              // status moves (power 0): type-coloured swirl round the user
  clear()                       // remove + dispose everything now, resolve promises
}
```

A **spot** is `{ pos: Vector3 (model centre), top: number (head y), r: number (half width) }` or `null`;
every method returns `Promise.resolve()` at once when `!this.on`, a spot is `null`, or a position is not
finite. `attack()` picks `SIG[moveId]` if the move is `sig` and a recipe exists, else `TRAVEL[type]`,
else `TRAVEL.normal`; same fallback for `IMPACT`. Wrap recipe creation and `step` in try/catch: an error
ends that effect quietly (pushes to `fx.errors`, tests check it is empty) and never breaks a battle.

**Recipe contract** (`fxrecipes.js` exports `TRAVEL`, `IMPACT`, `SIG`, `FX_COLORS`):
`(k, from, to, opts) => ({ dur, step(p) })` where `from`/`to` are spots and `k` is the kit:

| kit | what it gives |
| --- | --- |
| `k.points({ n, tex, size, colors, glow, opacity })` | owned `THREE.Points` (n ≤ 80) with `.set(i, x, y, z)`, `.color(i, hex)`, `.fade(a)`; positions start hidden (y = −1e4) |
| `k.mesh(geo, { color, glow, opacity })` | `'box' \| 'ring' \| 'disc' \| 'cone'` shared geometry, owned `MeshBasicMaterial` |
| `k.sprite(tex, { color, size, glow, opacity })` | owned `SpriteMaterial`, shared texture |
| `k.seeds(n, m)` | `Float32Array(n*m)` of `Math.random()` |
| `k.dir`, `k.side`, `k.dist` | unit vector from→to (flat), perpendicular, distance |
| `k.at(t, out, lift)` | point on the path at t, with an arc of height `lift` |
| `k.ease`, `k.wave` | `easeOut`, `sin(pi t)` |

Textures (drawn once on canvases): `dot` (soft round), `star` (4-point), `leaf`, `bubble` (ring with
shine), `shard` (diamond), `note` (♪ drawn as a path, not a font glyph), `bone`, `skull`, `z`, `plus`,
`up` (▲ arrow), `down`, `puff` (cloud), `bang` (!). Fonts differ on iPad, so draw shapes with paths.

## 3. The 19 type recipes (`fxrecipes.js`)

Travel = `TRAVEL[type]` (awaited, 350–450 ms). Impact = `IMPACT[type]` (300–400 ms, once per hit).
Colours are hex in `FX_COLORS[type]` (an array; rainbow/cosmic/alien have several).

| type | travel | impact | sound `fx:<type>` |
| --- | --- | --- | --- |
| normal | short white streak of 6 dots | grey **dust puff** (8 `puff`) + yellow impact **star** sprite that pops | soft whoosh (noise 1200 Hz) |
| fire | 30 orange/yellow **embers** along a low arc, flickering size | flame burst: embers rise and fade | crackle (3 short noise pops) |
| water | 20 `bubble`s wobbling along the path | **splash**: 16 blue dots arc up and fall | blip-blip (sine slides up) |
| grass | 14 `leaf`s spiralling round the path | leaves **swirl** in a ring and drift down | rustle (high bandpass noise) |
| electric | **zig-zag bolt**: 7 thin boxes between jag points (re-jag every 90 ms) | 12 yellow sparks spray | buzz (square, short slide) |
| rock | 6 brown box **pebbles** thrown in an arc | pebbles **fall** from above the target and bounce once | two low thuds |
| ice | 8 `shard`s flying straight, spinning | shards burst out + white frost dots | high tinkle (triangle 2 notes) |
| bug | **buzz** of 24 dots in a jittery swarm | swarm circles the target | short sawtooth buzz with tremolo |
| ghost | a dark **shadow** sprite swoops up and dives (arc lift 1.5) | purple wisps spiral up | "woo" sine slide down |
| mind | 3 pink **rings** grow while travelling (face the target) | rings pulse round the target's head | wobbly sine (vibrato) |
| metal | silver **sparks** shot like rivets (12 dots, glow) | bright spark spray + grey ring | clink (high short bell) |
| toxic | 14 **purple bubbles** in a lazy arc | bubbles pop into a small purple cloud | low blorp (sine slide down) |
| pixie | pink/white **sparkly dust** (`star`, glow) trail | sparkle ring that twinkles | twinkle (2 high notes) |
| drake | **roar wave**: 3 violet rings growing from the attacker's mouth | ring shock + violet dust | growl (low lowpassed sawtooth) |
| rainbow | **rainbow beam**: 5 thin coloured boxes from→to, grows then fades | rainbow star burst | quick 3-note up-run |
| cosmic | a **comet** (big glow dot + tail of 16 stars) | 10 tiny stars burst | shimmer sweep (triangle slide up) |
| sound | **music notes** (`note`) + 2 teal **sound rings** | notes bounce off the target | soft 2-note chirp (only for sound moves without their own sound) |
| bone | 3 spinning **bones** (`bone` sprites) | clatter of bones + small `skull` **puff** | clack-clack (short square 800/600 Hz) |
| alien | green **tractor beam** (cone, narrow end at attacker) + travelling green rings | green/violet rings shrink onto target | theremin (sine with vibrato, slide) |

## 4. Signature and status effects

Signature travel (`SIG[moveId]`, ≤ 700 ms, then the type impact with `{ big: true }` = 1.5× count/size):

| move | effect |
| --- | --- |
| blazedash | trail of embers along the attacker's lunge path, then a ring of flame round the target |
| royaltide | a blue wave wall (box scaled up, then forward) rolls to the target; gold sparkles on top |
| rootslam | green vine boxes shoot up out of the ground under the target, leaves fly |
| zenithray | wide rainbow beam (5 bands, twice as thick) + golden star burst |
| rattledance | 5 bones orbit the attacker, then fly at the target |
| mothership | blocky saucer (disc + box dome) drops above the target, green beam cone + rings |
| bigbong | a big gold gong ring expands from the attacker + a fountain of notes |

Status (`fx.status(kind, spot, opts)`, 600–900 ms, never awaited):

| kind | when | look |
| --- | --- | --- |
| `heal` | applyFx heal | green `plus` sparkles rise round the user + a soft green disc at its feet |
| `up` | raise (opts.stat) | 3 `up` arrows rise; atk red-orange, def blue, spd yellow-green |
| `down` | lower | 3 `down` arrows sink round the target, same colours, dimmer |
| `sleep` | sleep starts, and each "fast asleep" turn | `z` sprites float up from the head, growing, zig-zag |
| `flinch` | "flinched and couldn't move" | yellow `bang` pops over the head + 4 small stars circle |
| `recoil` | "hurt by the crash" | small dust puff + tiny star on the attacker |
| `miss` | "But it missed!" | grey whoosh puff beside the target (offset by `k.side`) |
| `power` | boss powerUp() | gold stars spiral up the champion's creature |
| (multi) | multi-hit moves | no extra kind: one `impact` per hit already shows each hit |

`aura(type, spot)`: 12 particles in the type's colours circle the user once (used for every status move:
Rest Up, Iron Wall, Sap Sip, Lullaby...), started before `applyFx`.

## 5. Battle wiring — `src/battle.js` (builder A)

1. New helper (no rng):
   ```js
   spot(side) {
     const m = this.modelOf(side);
     if (!m || !m.parent || !m.visible) return null;
     const box = new THREE.Box3().setFromObject(m);
     if (box.isEmpty()) return null;
     const pos = box.getCenter(new THREE.Vector3());
     return { pos, top: box.max.y, r: Math.max(0.3, (box.max.x - box.min.x) / 2) };
   }
   ```
   `const fx = this.game.fx;` everywhere below; guard with `fx?.` (the moves spec drives `useMove`
   without models, so spots are `null` and nothing plays).
2. `useMove`: flinched branch → `fx?.status('flinch', this.spot(side))`; asleep branch →
   `fx?.status('sleep', this.spot(side))` next to `sound.play('snooze')`.
3. Replace `sound.play(moveId)` with `sound.play(sound.has(moveId) ? moveId : `fx:${mv.type}`)`.
4. Keep `await this.lunge(side); await wait(150); const hit = this.rng();` exactly as is (draw order).
   Miss → `fx?.status('miss', this.spot(other))` before `say('But it missed!')`.
   Status move (`!mv.power`) → `fx?.aura(mv.type, this.spot(side))` then `applyFx` as now.
   Damaging move → after the `fx.kind === 'multi'` hits draw and the damage maths (all rng draws
   stay where they are), **before the hit loop**: `await fx?.attack(moveId, this.spot(side), this.spot(other))`.
   (Computing the spots does not draw numbers; awaiting does not change the order of draws.)
5. Hit loop: next to `this.flash(...)` add `fx?.impact(mv.type, this.spot(other), { big: !!mv.sig })`
   (not awaited). Keep `flash` and its timing.
6. Recoil: `fx?.status('recoil', this.spot(side))` inside `if (atk.hp < was)`.
7. `applyFx`: heal → `status('heal', spot(userSide))`; raise → `status('up', spot(userSide), { stat })`;
   lower → `status('down', spot(targetSide), { stat })`; sleep → `status('sleep', spot(targetSide))`.
   Each right after the existing `sound.play(...)`, none awaited.
8. `powerUp`: `fx?.status('power', this.spot('foe'))`.
9. Cleanup: in `start()`, call `g.fx?.clear()` at the very start and right after the turn loop
   (before the "Continue exploring" button and before models are removed/disposed). Effects only hold
   copied positions, never model references, so disposing models mid-effect is safe anyway.

Net extra time per damaging move ≈ 400 ms (the awaited travel). Nothing calls `say()` from fx, so the
battle log (and pvp's `history.length` check) is unchanged.

## 6. `main.js`, `index.html`, `sound.js`

- main.js: `import { Fx } from './fx.js'; game.fx = new Fx(scene);` next to `game.battle`; in `frame()`
  call `game.fx.update(now)` once per frame in both branches (before `renderer.render`); `goToMenu()`
  calls `game.fx.clear()`. Pause toggle exactly like the sound button: `<button id="fx-btn"></button>`
  after `#sound-btn` in `index.html`, text `✨ Effects on` / `✨ Effects off`, `stopPropagation`.
- sound.js (builder B): `has(name) { return !!SOUNDS[name]; }` on `sound`; 19 `'fx:<type>'` entries
  (table §3; vol ≤ 0.25, length ≤ 0.35 s, built from `tone`/`noise`/`notes`/`bell`/`drum`). Names with a
  colon can never clash with a move id. Builder A adds `has()` and only `'fx:normal'` so wiring works.

## 8. Spec `tests/specs/fx.mjs`

Setup like `moves.mjs`: new game, stone platform at y = 42, daytime (`g.time = 0.25`), then start a weak
wild battle (thunderwolf vs a 1-HP fluffin, `startWeakBattle` copied from moves.mjs) and wait for the move
buttons: the battle now waits for a choice, the camera frames both creatures, and
`b.spot('ally')` / `b.spot('foe')` give real positions. Then `pause(page)`. All effect calls below are made
from `page.evaluate` on `window.pokecraft.fx`.

1. **Warm-up:** start every `TRAVEL` and `IMPACT` type, every `SIG`, every status kind and `aura('fire')`
   at once; await all. Then record the baseline: `renderer.info.memory.{geometries,textures}`,
   `fx.root.children.length` (0), `scene.children.length`, `fx.stats`.
2. **Added and removed, per type:** for each of the 19 types: `fx.hold = 0.5`, start `attack(<first move
   of that type>)` and `impact(type)`, wait until `renderer.info.render.frame` has advanced twice, check
   `fx.root.children.length > 0`, every Points position is finite (no NaN), live points ≤ 300 and
   draw calls − idle calls ≤ 12; then `fx.hold = null`, await, wait 2 frames, check root is empty. At the
   end: memory geometries/textures equal the baseline, `scene.children.length` unchanged,
   `stats.made === stats.disposed`, `fx.active.size === 0`, `fx.errors` empty.
3. **Same for each `SIG` move and each status kind** (`heal`, `up` ×3 stats, `down`, `sleep`, `flinch`,
   `recoil`, `miss`, `power`) and `aura`.
4. **Off switch and clear():** `fx.setOn(false)` → `attack()` resolves at once and adds nothing;
   on again; start 3 effects with `hold`, call `fx.clear()` → root empty, promises resolved, stats balanced.
   Pause screen shows `#fx-btn` "Effects on"; clicking turns it off and `localStorage['pokecraft-fx'] === 'off'`.
5. **Battle still finishes and rng is untouched:** (a) in a fresh `page.evaluate` like moves.mjs part 2,
   with real models present, wrap `b.rng` in a counter and run the same `useMove` with fx on and off with
   the same scripted numbers: same number of draws, same damage, same log. (b) `playBattle(page)` finishes
   the open battle; afterwards root is empty. (c) frame time: median of 8 rAF deltas idle vs with the 3
   heaviest effects held (zenithray, mothership, electric): ratio ≤ 1.35 (log both numbers; software
   WebGL is noisy, so the draw-call/point checks in 2 are the strict budget).
6. **(B) Every type has its own recipe:** `Object.keys(TRAVEL)` and `IMPACT` cover all 19 types of
   `TYPE_COLORS`; every `sig` move in `MOVES` has a `SIG` entry; every type has an `fx:<type>` sound
   (`sound.has`) and they all play without `sound.errors`.
7. **(B) Contact sheet:** for fire, water, electric, grass, ice, ghost, rainbow, alien: `hold = 0.55` on
   `attack` (rainbow/alien: `0.7`), screenshot clipped to the middle of the screen, save
   `tests/screenshots/fx-<type>.png`; then open a blank page, `setContent` a 4×2 grid of those images
   (base64 `<img>` with a caption each) and screenshot it to `tests/screenshots/fx-sheet.png`. Take each
   screenshot right after the frame check (the game keeps running).
8. `!page.errors.length`.

Sound names like `'fx:fire'` need no `RESERVED_SOUNDS` entry in moves.mjs (a colon can't be in a move id); add a comment there saying so.
Re-run `pvp` (two browsers, both animate locally) and `moves` (rng order) after wiring.

## 9. Measuring speed on the slow renderer

Strict, deterministic budget: `renderer.info.render.calls` (≤ +12), live points (≤ 300), objects per
effect, `made === disposed`. Soft check: rAF frame-time ratio (≤ 1.35). For the owner's iPad: the toggle
in the pause screen turns everything off if it ever feels slow. The orchestrator should also compare the
total runtime of `battle-and-menu` and `gym` before/after (expected + ~0.4 s per attack).
