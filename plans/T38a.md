## 2. The Portal Door in the main world

### 2.1 Where (inside today's tower box)

`buildTower` (gymplace.js) has `R = 6`: walls at `|d| = 6`, door at `d = 6, s = -1..1`, rainbow pillars + lamps at
`d = 7, s = ±2`, a stone-brick ring at `fy` for `|dx|,|dz| <= 8` with air above, and `protect = pbox(x, z, 7, 1, 47)`.
The Portal Door stands **flat against the front wall, right of the pillar**, in the row `d = 7`, `side = [front[1], front[0]]`, `s = +3..+7`:

```
 d=7 row seen from the path:   s: -2  -1   0  +1  +2  +3  +4  +5  +6  +7
                                  P  [ tower door ]  P   F   ~   ~   ~   F     P = rainbow pillar + lamp
 y fy+6 lintel (F s 3..7), fy+7 one F crown at s 5         ~ = portal surface s 4..6, y fy+1..fy+5 (3 x 5)
```

- Posts `PORTAL_FRAME` at `s = 3` and `s = 7`, `y = fy+1..fy+6`; lintel `y = fy+6`, `s = 3..7`; crown `s = 5, y = fy+7`;
  surface `PORTAL_DIM` at `s = 4..6`, `y = fy+1..fy+5` (3 wide, 5 tall: bigger than the tower's 3 x 4 door). Floor
  stays the stone-brick ring. Two `LAMP`s are not needed (the frame glows).
- **Every cell is at `d = 7, |s| <= 7`, i.e. inside the tower's existing `protect` box (±7, y 1..47)**, and inside
  the ring `buildTower` already rewrites (air above `fy`). So no cell a player could ever edit changes: edits there
  were already dropped by `applyEdits` since T17. **No player build is lost, on any seed.** Nobody stands there
  (`TOWER.people` `at`: nurse `[4,-4]`, coach `[4,4]`, guards `[2,2]`, `[-1,-2]`, champion `[-4,0]`: all inside).
- Neighbourhood check (code, all seeds): gyms keep Chebyshev >= 23 from the tower (`towerSpot` gap 26/23), their
  boxes are ±7, so >= 9 cells of gap; caves keep out 18 blocks round the tower (`caves.js` mask); the new-land seam
  is >= 18 away (`towerSpot` keeps 18 from the 224 edges); treasure spot 0 is 8-16 from the tower and must clear
  `tower.protect` (unchanged area). Nothing is within reach of the door's box.

### 2.2 Code

- `src/portal.js` exports `PORTAL_AT = { d: 7, s0: 3, s1: 7, surface: [4, 6], h: 5 }` and
  `buildPortalDoor(world, tower)`: writes the cells with `world.set(..., false)`, returns
  `world.portal = { x, y: fy + 1, z, front, side, surface: [[x, y, z] x 15], frame, stand: [x, y, z, yaw] /* d 9, s 5, facing away */, box }`.

  It is a subset of `protect[0]`, so every rule that reads tower boxes (`protectedAt`, `fenced`, `treasureSpots`, the
  T38c spots) covers the door without naming it and gives the same answer as before: **treasure spots never move**.

  `newGyms: false`). `adoptOld` copies `portal` with the other bookkeeping keys (add `'portal'` to its list).

### 3.2 The terrain: `src/swirlland.js` (data + one loop; Node-runnable like `dreamland.js`)

Absolute coordinates on the 160 x 160 map. `y` = the top block of a deck (you stand at `y + 1`). Decks are 3 thick
(`SWIRL_STONE`, the top layer in a two-colour swirl pattern from `noise()` so the seed only changes looks).

```js

export const DOOR = { x: 39, z: [78, 82], y: [21, 25], facing: [1, 0] }; // PORTAL 5 wide x 5 tall, frame round it (z 77/83, y 26)
```

- **Spiral stairs:** steps of `SWIRL_STONE` round the pillar (ring at distance 2, one step up per cell, head room 2),
  starting at the hub's north edge and ending at the north deck's south edge. **Looping stairs:** a 1-wide square
  ring on `loopbase`: from its west corner it climbs 1 every 2 cells to `+4` and comes back down the other half to the
  start: you can walk round and round (once-per-trip toast: `These stairs go round and round... and round!`).
- **Lift streams** (`world.lifts = LIFTS`): no blocks. `Player.update`: `const lift = this.world.liftAt?.(this.pos)`
  (feet cell inside a box, realm worlds only; `World.liftAt` is 1 line reading `this.lifts`) -> skip gravity,

  walk onto it. Air control as usual. Riding: `riding.stop('quiet')` is not needed (sky riders ignore lifts).
  **Looks:** one `THREE.Mesh` per lift (a box `x/z` 2x2, `y0..y1+1`, `MeshBasicMaterial` transparent 0.45, additive,
  a small canvas texture of light-blue/pink stripes whose `offset.y` scrolls up every frame); built by
  `game.portal.reset(world)` in the Swirl, removed on leave. 4 draw calls; no world block, no meshing change.
- **Star bridge** (section 3.4) and **frames** (3.3) and the **Wizard's tower:** `WIZARD_STONE` 9x9 (`R 4`) on the
  wizard island, walls `y 21..40`, a stepped `WOOL.mind` cone `41..46`, `CRYSTAL` tip `47` (WORLD_H 48), `GLASS`
  windows with `LAMP`s behind them, a sealed door on its west face (2x3 `WIZARD_STONE` with a `STAR_STONE` star drawn
  with `setLive` above it, always lit). No way in.
- **Keep boxes** (`world.keeps`, see 3.6): door back `x 38-40, z 76-84, y 20-27`; each frame `+1` round its plane;
  the bridge corridor `x 60..wizard.x0, z 76-84, y 1-47`; the Wizard island + tower `±10, y 1-47`.
- **Metadata:** `world.swirl = { decks, lifts, frames: [{ spot, world, cells, cloth }], bridge: [{ world, cells }], wizard: { x, z, door } }`,
  `world.door = { surface, stand: [44.5, 21, 80.5, -Math.PI / 2] }` (the door back), `world.litCol.fill(1)` (no cave darkness under decks), `world.gyms = []`, `world.tower = null`.
- Cost: only decks, stairs and the tower are blocks (< 15 000 solid cells): far cheaper than the Dream. `perf.mjs --swirl`

### 3.4 The star bridge

- `n = PICTURE_WORLDS.length` stones; stone `i` is world `i`; cells `x 61+6i..65+6i, z 79-81, y 19-20`; gap 1 between
  stones (an easy step) and before the wizard island: `wizard.x0 = 61 + 6n` (n 7 -> island centre 112). Up to 12
  worlds still fit the 160 map (the spec checks `x1 <= 150`).
- In the world data the cells are **air**. `game.portal.update` in the Swirl: a lit stone (`game.stars` has the id)
  -> `setLive(STAR_STONE)` on its cells; unlit -> a pale gold box outline (`THREE.LineSegments`, the 12 edges of each
  5x3x2 box: export `GHOST_EDGES` from `obstaclecourse.js` or copy it), one geometry for all unlit stones. You can't
  stand on an outline: before the stars, the Wizard's tower can be seen but not reached. A fall lands on the cloud
  sea; the `wizard` lift brings you back.
- Looking at an outline is not possible (raycast hits only solid blocks), so the hint is a toast once per trip when you
  stand at the bridge's start (`x 58-60`): `A star bridge will grow here: one stone for every star from a Picture World.`
- Wizard door use / breaking: `The Wizard is inside, holding the Swirl together. Bring him stars!`.

## 5. Save format and play together

- New optional fields: `stars: string[]`; `place: 'swirl'`, `realmPos`, `realmEdits.swirl`, `realmVersions.swirl: 1`
  (all by T31/T35 code once `REALMS.swirl` exists). In the Swirl, `pos` = `world.portal.stand` (the stashed `ret`).
  `restore` loads the Swirl at `realmPos` like the Dream. Old saves: no change; a Swirl save opened by older code
  loads in main (unknown place).
- **Play together** (T38b does realms together): a guest using the door gets `Go through the Portal Door in your own
  world!`; the host's avatar in the Swirl is hidden for guests (T31 `Avatar.here`), with the def's `away` toast; the
