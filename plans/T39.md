## 2. T39b · One-button answers

### Rule
- **Yes = the same button that asked:** E, Enter (and Space? no: Space is jump, Q3), a tap on the touch action
  button, a click on the Yes button, a mouse click (left) while pointer-locked, Y (kept for old habits).
- **No = Esc, N, Backspace, "Not now", walking away / timeout** (as today). Esc while pointer-locked: the browser
  takes the lock; `pointerlockchange` with `ui.asking` -> `askNo()` and the pause screen shows as today (one click goes
  on). Tapping the screen outside the box does **not** cancel on iPad (kids tap and drag a lot; Q4).
- **No double press:** `ui.ask` stores `openedAt` and `kind`. A yes counts only if it is a fresh press: keydown with
  `!e.repeat`, and at least **350 ms** after the box opened for a question you started (`kind: 'mine'`: bed, rematch,
  follow-after-asking). Questions that **come to you** (`kind: 'incoming'`: duel, co-op giant, hide and seek, the
  automatic follow offer) take E / tap only after **1 s**, so an E meant for a leader can't accept a friend's battle by
  accident; Y and the button work at once as today. While a question is open, E / tap / click never also talk, break
  or battle (main.js checks `ui.asking` before `interact` / `breakBlock`).
- **Words:** the hint under the box becomes per device: desktop "E = Sleep · Esc = Not now" (built from `yes`/`no`),
  touch: no hint, the Yes button is the big one (min-height 64) and the blue action button says the Yes word too
  ("Sleep", "Battle!", "Let's play!", "Follow"). `ui.ask` options lose the free-text `hint`; callers pass `kind`.
- **Placement on iPad:** `#ask` moves down below the top bar (top: 80 px on touch) so it never covers the menu.

### `ui.ask` API (`ui.js`)
`ask({ text, yes, no, onYes, onNo, kind = 'mine' })`; `askYes(how)` with `how` = `'key' | 'tap' | 'button' | 'click'`
applies the fresh-press rule (`canConfirm(how, e)`); `asking`, `asked`, `closeAsk` stay. **The duel box joins it:**
`duel.js` uses `game.ui.ask({ kind: 'incoming', ... })` instead of its own `#duel-ask` (removed from index.html), so
there is one box and one key rule (if a rematch box is open, the duel is answered "busy" as today's
`hideseek busy()` does; `rematch.offer` already refuses while `duels.incoming`).

### Per use

| Use | Change |

| Bed | E / Enter / tap Sleep / click = sleep (the "use the bed again" branch stays but is no longer needed: any yes works even when you look away); Esc / N = not now |
| Rematch | same; the hint "or click the leader again" goes (a click is a yes anyway) |

| Battle "Continue exploring" | unchanged (E / Enter / Space already) |

## 3. T39c · Tablet controls

### Rule: buttons never move (owner, 2026-10-25)

The owner asked: if buttons come and go, the layout keeps changing and that is hard for a child. So the rule is
**fixed slots**: every button has one place that never changes, and it is always there while it could ever be useful
to you. When it can't do anything right now it is **dimmed** (greyed, still the same size and place, a tap gives a
short hint toast instead of nothing), never hidden. The only thing that changes is the **word** on the big action
button (that is the point of it: it tells you what E / tap will do). Muscle memory wins over a tidy screen; the screen
gets calmer by having fewer buttons, not by hiding them.

### Proposal (nothing lost, fewer buttons, none that jump around)
```
 [☰]  [Book]          (top, left of centre)            clock / badges / 📍 guide ▾ / chip
 party-mini (tap = Team)

 joystick                                      [ Ride ]  [ Place ]     <- fixed slots, dimmed when they can't act
                                               [  ACTION  ] [ Jump ]   <- fixed, always
               hotbar (tap = pick, tap again = Blocks)
```
- **One big action button** `#btn-act` (round, 100 px, always there in the same place, dimmed when it can do nothing)
  whose label says what it will do: **Battle! / Talk / Heal / Open / Sleep / Wake up / Press / Go in** for targets
  (today's `setAction` words, shorter), and **Break** when you look at a breakable block in reach. It replaces Break:
  today `btn-break` already battles a creature under the crosshair first, so one button = "do the thing I look at".
  While a question is open it shows the Yes word (T39b). Breaking stays one press per block (as today).
- **Place**: always in its slot; dimmed when the crosshair hits nothing you may build on, or the picked block is a
  limited one at `×0` (tap while dimmed: "Look at a block to build on it!" / "You have none left").
- **Ride**: the slot is there as long as a rideable creature is in your team (that changes rarely, when you change your
  team, never while walking around); dimmed where you may not ride (gym fences, hide and seek), a tap says why. Without
  a rideable creature the slot is empty (an outline ring would only confuse).
- **Jump**: always (84 px, as today; says "Up" while flying).
- **Down while flying** takes the **Place** slot (you don't build in the air; the button keeps its place and colour,
  only its word and icon change, like the action button). Open question Q9 below.
- **Top bar:** `[☰]` opens the pause screen, which gets big buttons **Team, Blocks, Book, Missions (Champions),
  Where to go, My home (on a mat)**, then Sound / Effects / Play together / Main menu. **Book** keeps its own button
  (the boy uses it a lot, Q6). **Team** moves to a tap on `#party-mini` (the creature card top left; it gets a little
  "Team" label on touch) and stays in ☰. **Blocks** stays on the hotbar (tap the picked slot) and in ☰. Missions stay
  on the chip; Where to go on the guide line (T39a).
- **`#ask` below the top bar**, buttons 64 px (T39b). Toasts unchanged.
- Sizes for a child: the action button 100 px, Jump 84, context buttons 64-72, top buttons 56 high; every HUD
  thing you can tap (party card, guide, chip, hotbar) at least 44 px high on touch.
- `TouchControls` gets `setButtons({ act: { label, dim }, place: { dim, why }, ride: { have, dim, why, on }, sky })` (one call per frame
  from main.js, DOM written only on change, like `setRide`); `setAction`/`setRide` become wrappers so old callers and
  tests still work. `actions.interact` becomes "action": ask -> yes, else target -> `interact(true)`, else
  `breakBlock()`, else My home.

### Desktop key hints
- Prompt words stay ("Bed · E to sleep"); the ask hint is built from the keys (T39b).
- Pause screen and title controls list gets the missing keys: **E** use / talk, **G** where to go, **M** missions,
  **H** home (on a Doormat), **R** ride, **Esc** cancel / pause. Touch controls text updated for the new layout.
