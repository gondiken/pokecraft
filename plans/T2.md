# T2 · Weather: build plan

Read `CLAUDE.md` and the T2 section of `ROADMAP.md` first. All weather logic goes in a **new
`src/weather.js`**. Edits to shared files (`main.js`, `creatures.js`, `sound.js`, `multiplayer.js`)
stay small: T1 (Creature Book) and T5 (Final boss) edit `main.js`/`ui.js`/`battle.js` in parallel,
so add code in the spots named below, never reformat or move existing code. Do not touch
`species.js` data, `world.js`, `ui.js`, `battle.js`, `gyms.js`.

## Scope

- Required: **rain**, **storm** (lightning flashes + quiet thunder), **snow**, **rainbow after rain**.
- Extras (cheap, reuse the same particles/tint): **sandstorm** (desert, instead of rain),
  **swamp fog** (misty mornings), **shooting stars** (clear nights).
- Skipped: aurora, windy days (more meshes/animation for little gain; backlog).

## 1. The shared state and the per-place weather

One shared **phase**: `'clear' | 'rain' | 'storm' | 'rainbow'`, with `left` = game seconds
remaining. Timers advance with the game's `dt` (same capped `dt` as day/night, `DAY_LENGTH` = 480 s).
Only the solo player / host runs the timer; a visitor copies the host's phase (section 7).

Phase machine (`tick(dt)`), all random choices through `this.random()` (defaults to `Math.random`,
tests replace it):

| Phase | Lasts (game s) | Then |
| --- | --- | --- |
| clear | 180–360 | rain |
| rain | 100–180 | 35 %: storm, else *end of wet* |
| storm | 60–100 | *end of wet* |
| rainbow | 120–180 (ends at once if night falls) | clear |

*End of wet*: if it is daytime (`Math.sin(game.time * 2π) > 0.15`) → rainbow, else clear. So every
daytime rain ends in a rainbow (deterministic, kid friendly; rainbows stay rare because rain is).
`reset()` (new game / continue / back to menu): phase clear for 240–360 s, so existing specs almost
never meet random weather (tests run at ~0.05 game s per frame).

Effective weather **kind** at a place, `kindAt(biome)`:

| Biome group | clear phase | rain | storm | rainbow |
| --- | --- | --- | --- | --- |
| WET: plains, meadow, forest, swamp, beach, mountain, `water` | clear¹ | rain | storm | rainbow |
| COLD: taiga, snow, peak | clear¹ | snow | snow | rainbow |
| desert | clear¹ | sandstorm | sandstorm | rainbow |

¹ clear becomes `'stars'` at night (any biome), and `'fog'` in **swamp** in the morning
(hours 5–10, i.e. `game.time >= 0.958 || game.time < 0.167`; `hours = (time*24+6)%24`).
If `this.forced` is set (debug `set()`), `kindAt` returns it for every biome.

`here` = `kindAt(world.biome(player x,z))`, or `'water'` → WET via `creatures.biomeAt`-like check
(`world.surface(x,z).id === B.WATER`). Recompute at most every 500 ms of **real time**
(`performance.now()` timestamp, not dt — robust at 1–2 fps), and immediately in `set()`/`snap()`.

## 2. Spawn boosts (multipliers, never 0)

`BOOSTS` in weather.js, by kind → type → multiplier (missing = 1). All values > 0.

| kind | boosts |
| --- | --- |
| rain | water ×3, grass ×1.5, fire ×0.5 |
| storm | electric ×4, water ×2, fire ×0.5 |
| snow | ice ×3 |
| sandstorm | rock ×2.5, fire ×1.5 |
| fog | ghost ×3, toxic ×2 |
| stars | cosmic ×2 |
| rainbow | rainbow ×10 |

`boost(biome, type)` = `BOOSTS[kindAt(biome)]?.[type] ?? 1`. Boosts use the **spawn column's**
biome (so standing at a forest edge, creatures spawning in the snow get snow boosts).

`src/creatures.js` (only change): add `this.weather = null;` in the constructor and split
`pickEntry` into a weights step (keep `pickEntry`'s signature and return value):

```js
// Spawn table entries with their weights, after the weather's boosts: [[entry, weight], ...]
weights(biome, night) {
  const wx = this.weather;
  return SPAWNS[biome].filter(([, , when]) => !when || (when === 'night') === night)
    .map(e => [e, e[1] * (wx ? wx.boost(biome, SPECIES[e[0]].type) : 1)]);
}
pickEntry(biome, night) {
  const table = this.weights(biome, night);
  const total = table.reduce((a, [, w]) => a + w, 0);
  let r = Math.random() * total;
  for (const [e, w] of table) if ((r -= w) < 0) return [e[0], e[2]];
  return [table[0][0][0], table[0][0][2]];
}
```

## 3. `src/weather.js` API

```js
import * as THREE from 'three';
import { B } from './blocks.js';
import { sound } from './sound.js';
export const KINDS = ['clear','rain','storm','snow','sandstorm','fog','stars','rainbow'];
export const BOOSTS = {...};
export class Weather {
  constructor(game, hooks)  // hooks: { toast(text), changed() } ; builds points, arc, star line, adds to game.scene
  phase, left, forced, here, biome, mix, random, flashes  // readable fields (flashes = lightning count)
  reset()                    // clear phase, forced = null, hide everything, sound.setAmbience(null)
  tick(dt)                   // phase timer only (skipped when game.mp.role === 'guest'); also lightning/thunder timers
  update(dt, now)            // per frame while playing: tick, recompute `here` (500 ms throttle), particles, arc, stars, ambience, toasts
  kindAt(biome)              // section 1
  boost(biome, type)         // section 2
  boosts()                   // BOOSTS[here] as a plain object ({} when clear)
  sky(light)                 // tint for main.js, section 4
  set(kind, seconds)         // debug: see below
  skip()                     // end the current phase now (runs the normal "then" rule), clears forced
  snap()                     // recompute `here` now and jump visuals to full strength (mix = 1)
  state()                    // { phase, left: Math.round(left), forced } for multiplayer
  apply(s)                   // visitor: take host's state (phase, left, forced) then snap()
  info()                     // { phase, here, biome, forced, left, boosts: boosts(), particles: points.visible ? count : 0, rainbow: arc.visible }
}
```

`set(kind, seconds)`: kind must be in KINDS (else throw). Sets `forced = kind === 'clear' ? null : kind`
and the matching phase (`snow`/`sandstorm` → rain; `storm` → storm; `rainbow` → rainbow;
`clear`/`fog`/`stars` → clear), `left = seconds ?? normal duration`, then `snap()` and `hooks.changed()`.
`forced` is cleared whenever the phase changes on its own (or by `skip()`), so after
`set('rain')` + `skip()` the normal rainbow rule applies.

Each phase change (natural, `set`, `skip`, `apply`) calls `hooks.changed()`.

## 4. Sky, fog, light (main.js `updateSky`)

Visuals fade with `this.mix` (0..1): when `here` changes, `mix` falls to 0 at 0.5/s, the shown
kind switches, then rises at 0.5/s. `set/snap/apply` jump straight to mix 1.

`sky(light)` returns `{ tint: THREE.Color, amount, dim, fogNear, fogFar, flash }` (reuse one
Color object). Tint colour is multiplied by `0.25 + 0.75 * light` so nights stay dark.

| kind | tint | amount | dim (×brightness) | fog near/far |
| --- | --- | --- | --- | --- |
| clear, stars, rainbow | – | 0 | 1 | 40 / 100 |
| rain | 0x7d8a99 | 0.6 | 0.8 | 30 / 80 |
| storm | 0x4a5260 | 0.75 | 0.65 | 25 / 70 |
| snow | 0xd0dae6 | 0.5 | 0.9 | 25 / 75 |
| sandstorm | 0xd8b878 | 0.7 | 0.85 | 12 / 45 |
| fog | 0xc8d0d0 | 0.65 | 0.9 | 8 / 35 |

Values lerp from the clear values by `mix`. `flash` is 0..1 during a lightning flash.

Edit in `updateSky` (after `const brightness = ...`), replacing the background/fog/material lines:

```js
const wx = game.weather.sky(light);
scene.background.copy(NIGHT_SKY).lerp(DAY_SKY, light).lerp(wx.tint, wx.amount);
if (wx.flash) scene.background.lerp(FLASH, wx.flash * 0.7);          // const FLASH = new THREE.Color(0xe8eeff)
scene.fog.color.copy(scene.background);
scene.fog.near = wx.fogNear; scene.fog.far = wx.fogFar;
const lit = Math.min(1, brightness * wx.dim + wx.flash * 0.4);
materials.solid.color.setScalar(lit);
materials.water.color.setScalar(lit);
```
Leave `materials.glow` alone (the blocks spec checks lamps stay at 1). Add the HUD clock icon:
`game.ui.setClock(\`${...} ${hh}:${mm}${game.weather.icon}\`)` where `icon` is `''` for clear,
` ☔` rain, ` ⛈` storm, ` ❄` snow, ` 🌈` rainbow, ` 💨` sandstorm, ` 🌫` fog, ` ✨` stars.

## 5. Visuals in weather.js

**Particles**: one `THREE.Points`, `MAX = 500` points, `BufferGeometry` position attribute
(Float32Array) filled randomly in a box x,z ∈ [-12, 12], y ∈ [-8, 10], positions *relative to the
camera*; each frame `points.position.copy(game.camera.position)`. `frustumCulled = false`,
`renderOrder = 2`. `PointsMaterial({ size, map, transparent: true, depthWrite: false, opacity, color })`.
Textures: two small `CanvasTexture`s drawn once: a thin vertical streak (8×32 canvas, line in the
middle) for rain/storm; a soft round dot (16×16 radial gradient) for snow/sand.
Per kind (`setDrawRange(0, count)`):

| kind | count | size | colour / opacity | motion per second |
| --- | --- | --- | --- | --- |
| rain | 350 | 0.35 | 0xaaccff / 0.55 | y −14 |
| storm | 500 | 0.4 | 0x9ab0d0 / 0.6 | y −18, x +3 |
| snow | 300 | 0.15 | white / 0.9 | y −1.5, x/z sin wobble |
| sandstorm | 400 | 0.1 | 0xd9b77a / 0.7 | x +9, y −0.5 |

Wrap each coordinate back into the box (modulo) so points never run out; opacity × mix.
Hidden (`visible = false`) for other kinds, and when **covered**: a solid block within 15 above the
player's head (check `world.get(x, y, z)` up the column, in the same 500 ms throttle; lets gyms and
houses stay dry).

**Rainbow arc**: `RingGeometry(70, 80, 48, 7, 0, Math.PI)` with vertex colours by radius (7 bands
red→violet, outer = red), `MeshBasicMaterial({ vertexColors: true, transparent: true, opacity: 0.45 * mix,
side: DoubleSide, depthWrite: false, fog: false })`. Each frame position = camera position +
(0, −12, −130) (fixed world direction north, −z; yaw 0 looks at it). Visible only for kind rainbow.
Camera far plane is 300, so it renders past the fog.

**Lightning** (kind storm): timer 6–14 s (game dt); on strike `flashes++`, `flash = 1` decaying
over 0.25 s (use `Math.max(flashTimer...)` with dt; to look right at 60 fps), and schedule thunder
0.5–1.5 s later (a dt countdown in `tick`, not `setTimeout`) → `sound.play('thunder')`.

**Shooting stars** (kind stars): one `THREE.Line` (2 vertices, `LineBasicMaterial({ color: 0xffffff,
transparent: true, fog: false })`), every 10–25 s place it ~150 away at a random direction, 60–90
up, and slide it over ~1 s (fade opacity). First one per night → toast + `sound.play('star')`.

## 6. Toasts and sound

Toasts via `hooks.toast` (main.js only shows them when `game.started && !game.inBattle`). When
`here` changes to a kind, toast at most once per kind per 120 game seconds:

- rain: "It's raining! Water creatures love the rain."
- storm: "A thunderstorm! Electric creatures love this."
- snow: "Snow is falling. Ice creatures come out to play!"
- sandstorm: "A sandstorm! Rock and fire creatures like the hot wind."
- fog: "A misty morning... ghost creatures hide in the fog."
- rainbow: "A rainbow! Rainbow creatures love this." (+ `sound.play('rainbow')`)
- stars (first shooting star of a night): "A shooting star! Make a wish. Cosmic creatures are out tonight."

`src/sound.js` additions (keep the existing code as is):

- In `audio()`: also make `longNoise`, a 2 s noise buffer.
- SOUNDS: `thunder` (lowpass ~150 Hz noise from `longNoise`, 1.8 s, slow attack 0.15 s, peak gain
  0.35, plus a second softer rumble at +0.4 s); `rainbow` (`notes([784, 988, 1175, 1568], 0.09,
  { len: 0.18, type: 'triangle', vol: 0.25 })`); `star` (`notes([1568, 2093], 0.12, { len: 0.2, vol: 0.18 })`).
- Ambience loop: `sound.setAmbience(name)` with name `'rain' | 'storm' | 'wind' | null`. One looping
  `BufferSource` on `longNoise` → biquad → gain → master, created lazily; levels rain 0.10
  (lowpass 1200 Hz), storm 0.15 (lowpass 900), wind 0.06 (bandpass 400, Q 0.7; used for sandstorm
  and snow at 0.03). Fade with `gain.setTargetAtTime(level, now, 0.8)`. Store `sound.ambient = name`
  and `sound.ambientLevel` (the level actually applied: 0 when `!sound.on`). `setOn()` must re-apply
  the ambience (off → 0). Wrap in try/catch pushing to `sound.errors`, like `play`.
- weather.update calls `sound.setAmbience(...)` only when the wanted name changes (and with null
  when covered or on the title screen / `reset()`).

## 7. Multiplayer (host → visitors)

`src/multiplayer.js`:
- `sendState()`: add `weather: this.role === 'host' ? g.weather?.state() : undefined`.
- `on('state')`: next to the `time` line, `if (p.host && this.role === 'guest' && p.weather) this.game.weather?.apply(p.weather);`
  (apply should be a no-op if phase/forced are unchanged, only `left` is copied).
- `sendWorld()`: add `weather: g.weather?.state()` to the message; in `on('world')` add `weather` to the
  destructure and to the `gotWorld({...})` object.
`main.js` `loadWorld` hook: after `game.time = data.time;` add `if (data.weather) game.weather.apply(data.weather);`.
Visitors never run the phase timer (`tick` checks `game.mp.role === 'guest'`). Going home reloads
the page, so their own weather restarts clear. Host's `hooks.changed` → `if (game.mp.role === 'host') game.mp.sendState();`
so changes arrive at once.

## 9. Save

**Not saved.** Weather restarts clear on load (it changes every few minutes anyway, and keeping the
save format unchanged avoids conflicts with T1's `seen`/`caught` save change).

## 10. Test: `tests/specs/weather.mjs`

Use `openGame` + `newGame` + the **platform trick** from `sound.mjs` (stone platform at y=42 by the
spawn point). Set `g.time = 0.25` (noon). Screenshots go to `tests/screenshots/weather-<kind>.png`
(`fs.mkdirSync(..., { recursive: true })`; add `tests/screenshots/` to `.gitignore`); log the path.
Before screenshots: `pause(page)` not needed; set `player.yaw = 0; pitch = 0.15`, wait ~2500 ms.
Checks:

1. A new game starts `phase === 'clear'`, `forced === null`.
2. For every kind in KINDS: `set(kind)` → `info().here === kind`; particles: for rain/storm/snow/
   sandstorm `info().particles` between 100 and 600 and `weather.points.visible`, for the others 0;
   `info().rainbow` only for rainbow. Screenshot rain, snow, rainbow (and storm optional).
3. Spawn mix, exact (deterministic, via `g.creatures.weights`): share of a type =
   sum of its weights / total. With `set('clear')` vs `set(kind)`:
   storm/plains/day electric share ≥ 2× clear; rain/swamp/day water ≥ 1.8×; snow/taiga/day ice ≥ 1.5×;
   rainbow/meadow/day rainbow ≥ 5× and ≥ 5 %; sandstorm/desert/day rock ≥ 1.5×;
   fog/swamp/night ghost ≥ 1.5×; stars/peak/night cosmic ≥ 1.3×.
4. Never zero: for every kind × every `SPAWNS` biome × day/night, every entry's weight > 0, and
   `pickEntry` returns a species (import SPAWNS via `await import('/src/species.js')` in evaluate,
   as blocks.mjs does).
5. Spawn simulation (real spawn path): with the player on the platform, `cm.clear()`, then 600×
   `cm.trySpawn(g.player.pos, g.spawnPoint, false)` with `cm.clear()` whenever `cm.list.length >= 16`,
   counting spawned types via a temporary `cm.onSpawn` wrapper; run under `set('clear')` and
   `set('storm')`. Check storm electric share > 1.5× clear and ≥ 20 spawns in each run. Restore onSpawn.
6. Rainbow after rain: `g.weather.random = () => 0.99` (no storm); `set('rain')`, `skip()` →
   `phase === 'rainbow'`, `info().rainbow`, `#toast` text contains "A rainbow!", `sound.played`
   includes `'rainbow'`. Natural timer too: `set('rain', 2)` then `for 60×: g.weather.tick(0.05)` →

7. Storm: `set('storm')`, `for 400×: tick(0.05)` (20 game s) → `flashes >= 1` and `sound.played`

9. Multiplayer (copy the join steps from `multiplayer.mjs`, `openPair`): host `set('rain')` *before*
